# 常駐（閉じていても動く側）

最終更新: 2026-09-19 ・ **実測で一周した**

> **2026-09-20 追記：この文書の前提は、半分だけ崩れました。**
> Android アプリ（`mobile/`）が動き、**閉じていても通知が鳴る**ようになりました。
> 「閉じたら何も起きない」は、いまは**ブラウザ（Artifact）だけの話**です。
>
> **そして下の仕組みは、Android アプリでは働きません。**
> `lifeos_memory` / `lifeos_results` は `db`（claude.ai 側）にあり、
> **APK には `db` が渡らない**ので（`window.claude` が無い）、
> 「留守のあいだに」は APK の画面に**一生出ません**。
> いまの常駐は **Artifact 専用**です。
>
> ただし**考える処理**が閉じている間に動かないことは、どちらでも変わりません。
> 通知は「先に予約したものが鳴る」だけで、新しく読み取ったり組み立てたりはしません。

## 分かったこと

**ブラウザのタブは常駐できません。** これは TELOS の C0 に本人が書いたとおりで、
アプリをどれだけ作り込んでも変わりません。

> 妨げているもの：アプリはブラウザのタブを開いている間しか存在しない。
> だから観測も、向こうからの声かけもできない

だから **常駐させるのは「考える側」** にしました。アプリは、その結果を受け取って見せる役です。

## 仕組み

```
本人がアプリで話す
   ↓（アプリが今までどおり notes / items に保存する。新しい道は作っていない）
db: notes / items
   ↓
【留守番セッション】session_015G21hw68GknfGJMwpGWsnU
   毎日 05:08（日本時間）に Routine が起こす
   trig_014mRGebyiR1iVSjS7cpBVsH（cron は UTC で "8 20 * * *"）
   アプリが閉じていても、このセッションが立ち上がって動く
   ↓ 読む：notes / items / lifeos_memory / lifeos_results
   ↓ 書く：lifeos_memory（記憶）／ lifeos_results（やったこと）※この2つだけ
db: lifeos_memory / lifeos_results
   ↓
次にアプリを開いたとき
   ・lifeos_memory → 依頼文の【LifeOSが覚えていること】に載る（前からあった）
   ・lifeos_results → チャットに「留守のあいだに」として出る（v8.1 で追加）
```

## 実測（2026-09-19）

| 確かめたこと | 結果 |
|---|---|
| 留守番セッションが保存先を**読める** | **できた**（notes 3件・items 9件・lifeos_memory 8件。実際の中身と一致） |
| 保存先に**書ける** | **できた**（`lifeos_results` に1件書いて、読み直して確認） |
| **定時の呼び出し**が届く | **届いた**（06:10:49 発火 → 06:11:08 に書き込み・`last_run` SUCCEEDED） |
| 何も無いときに黙っていられる | **できた**（記憶にすべきものが無く、1行も書かなかった） |

## つまずいた点（次のセッションへ）

- **まっさらなセッションを毎回作る形（`create_new_session_on_fire`）では書けません。**
  2回試して2回とも0件でした。`ArtifactData` が渡らないためです。
  **代わりに、`create_session` で `extra_allowed_tools: ["ArtifactData","ToolSearch"]` を
  指定したセッションを1つ作り、Routine の `persistent_session_id` でそこへ起こす**こと。
- **`fire_trigger`（手動発火）では、留守番セッションは起きませんでした。**
  7分待っても `updated_at` が動かず、何も書かれませんでした。
  **定時の発火（`run_once_at` / cron）だと起きます。**
  だから「手で発火して何も起きない」を「壊れている」と読まないこと。
  確かめるときは `run_once_at` を数分後に置くこと。
- **Routine の指示文（prompt）は、その Routine が投稿する会話からしか直せません。**
  別のセッションから直そうとすると断られるので、**消して作り直す**こと。
- 確認のために書いた行（`__selftest` / `__wake_test`）は**どちらも消済み**です。
  あれはアプリのチャットに「留守のあいだに」として出るので、残してはいけません。

## 決めたこと

- **`lifeos_requests` は作らない。** 発言は `notes` に全部あるので、向こうはそれを読む（決まり7e）
- **アプリは読むだけ。書かない。** 書くのは留守番だけ
- **何も変わっていなければ、何も書かない。** 毎日「何もありませんでした」と出さない
- **推測で人物像を作らない。** 本人が実際に言ったことだけ（決まり2・決まり11）
- 触ってよいのは `lifeos_memory` と `lifeos_results` の2つだけ。
  `notes` / `items` / `turns` / `docs` / `meta/settings` は**読むだけ**
- アプリのコードを変える・再公開する・GitHub に書く、は**禁止**
  （自動で毎日走るものに再公開をさせない。公開版を巻き戻す事故が起きる）

## これは「その人ひとり専用」の部分です

留守番セッションと Routine は本人のアカウントとこの環境に紐づいているので、
**配っても付いていきません**（決まり11）。
アプリ側のコードは誰が使っても動きます——つながっていなければ、
依頼文に見出しも出ませんし、チャットにも1行も出ません（決まり7「AIは任意」と同じ）。

## ブラウザ側で常駐できるかは、アプリが測って出します

設定タブのいちばん下に、**その端末で測った結果**が出ます（`#resideOut`）。
Service Worker / Periodic Sync / 端末の通知 / 控えが消されにくいか の4つ。
**測るだけで、登録も許可の要求もしません。**
どれが使えても、考える処理はタブを閉じると止まります。

## まだできていないこと

- **向こうから本人へ知らせる道**が無い（通知は出していない）。
  次にアプリを開くまで、やったことは本人に届きません
- 05:08 は**こちらが決めた時刻**です。本人が言ったわけではないので、変えたいときは言ってください
- 留守番がやるのは**記憶を整えること**だけです。予定を組む・調べる・連絡する、はまだしません
