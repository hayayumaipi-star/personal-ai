# Android の殻（Expo）

`app/index.html` を、そのまま Android アプリの中で動かすための**殻**です。

**中身のロジックは1行もここにありません。** 正は `app/index.html` だけ。
殻がやるのは3つだけです。

| 殻の仕事 | なぜ |
|---|---|
| `index.html` を WebView で開く | 5,500行と912件のテストを、そのまま使うため |
| AIへの通信を代わりに行う | WebView から直接呼ぶと、相手の受け入れ設定（CORS）に止められることがある |
| 予定の通知を予約する | **これが Android にする唯一の理由。** ブラウザではできない |

**「定時に自分で起きる」仕組みは入れていません。** 通知は先に予約しておけば
アプリが閉じていても鳴るので、要らないからです。入れない分だけ殻は小さく、壊れる場所も少ない。

**依存しているのは3つだけ**（`react-native-webview` / `expo-notifications` /
`react-native-safe-area-context`）。
本体の HTML は `sync.js` が**JSの文字列に変えて**渡すので、
資産ファイルを読む仕組み（`expo-asset` / `expo-file-system` / Metro の設定）は要りません。
版が上がって壊れる場所を、その分だけ減らしてあります。

3つ目の `safe-area-context` は**余白を測るためだけ**です。Android 15 以降は
画面いっぱいに描くのが既定なので、これが無いと**見出しが時計に、タブがホームバーに
潜り込みます**（2026-09-20・実機で起きた）。下のホームバーの高さは、
素の React Native では測れません。

## 試す（Expo Go でできます）

スマホに **Expo Go** を入れて、同じ Wi-Fi につないでおいてください。

**Windows なら、`mobile` フォルダの「スマホで試す.cmd」をダブルクリックするだけです。**

最新に更新して、足りないものを確かめて、初回の準備をして、QRを出すところまで1本でやります。

`.cmd` にしてあるのは、**PowerShell の既定では `.ps1` が実行を拒まれるから**です
（`.cmd` にはその制限がありません）。中身は `start.ps1` を呼ぶだけの4行で、
日本語は1文字も入れていません——`.cmd` は画面の文字コードで読まれるので、
日本語を入れると環境によって化けます。

PowerShell から直接打つなら：

```powershell
cd C:\Users\zaoji\personal-ai\mobile
.\start.ps1
```

（別のネットのスマホから開くときは `.\start.ps1 -Tunnel`）

自分で順に打つなら：

```bash
cd mobile
npm install          # 初回だけ
npm start            # sync してから expo start（QRコードが出る）
```

QRコードが出たら、**Expo Go のアプリの中から読み取って**ください
（Android のカメラアプリではなく、Expo Go の中のスキャナ）。
パソコンとスマホが**同じ Wi-Fi** につながっている必要があります。

**同じ Wi-Fi でつながらないとき**（会社や学校のネットだと弾かれることがあります）：

```bash
npm start -- --tunnel
```

外を経由するので、別のネットのスマホからでも届きます。
そのために `@expo/ngrok` を最初から入れてあります（聞かれずに始まります）。

**本体を直したら `npm start`（または `node sync.js`）を先に。** 忘れると古い画面が出ます。

**QRコードは、走らせたパソコンにだけ出ます。** QRの中身は
`exp://<そのパソコンの住所>:8081` で、スマホはその住所へ取りに行きます。
だから**別の場所で作ったQRは届きません**——住所がそこを指していないからです。
（開発用のコンテナで走らせて確かめたときの住所は `exp://192.0.2.2:8083` でした。
外から届かない住所なので、そのQRはどの端末でも開けません。）

## パソコンを使わずに済ませたいとき（APK を作る）

上の方法は、**パソコンが配っているものをスマホが見に行く**仕組みなので、
試すたびにパソコンで黒い窓を開く必要があります。

**APK を作れば、それが要らなくなります。** ふつうのアプリとしてスマホに入るので、
パソコンは一度きりで済みます。

**Windows なら、`mobile` フォルダの「APKを作る.cmd」をダブルクリック**するだけです
（更新 → 本体を写す → 組み立てを頼む、まで1本でやります）。

自分で打つなら：

```bash
cd mobile
node sync.js      # ← 忘れると古い中身の APK ができる
npx eas-cli@latest build -p android --profile preview
```

- **Expo の無料アカウントが要ります**（https://expo.dev/signup ・Google でも可）。
  `build-apk.ps1` は組み立てを頼む前に `eas whoami` で確かめ、
  入っていなければ `eas login` を呼びます（**既定でブラウザが開く**。
  `eas login --help` で確認済み・eas-cli 24.7.0）。
  **`build` から暗黙に走るログインは、窓の中でユーザー名とパスワードを聞いてくる。**
  そこで `Your username, email, or password was incorrect.` が出る（実機で報告）。
  **Google で登録した人にはパスワードが無いので、ここは必ず失敗する。**
  だから先に `eas login` を明示して呼び、ブラウザ側で入る。
  それも通らないときは**アクセストークン**（https://expo.dev/settings/access-tokens ）を作って
  `set EXPO_TOKEN=…`。パスワードを使わないので、登録のしかたに関係なく通る。
  ただし窓を閉じると消える。
- 初回は「プロジェクトを作るか」「Android の鍵を作るか」と聞かれます。**どちらも Y**
  （鍵はアプリに署名するためのもので、Expo が預かります）
- 組み立ては **Expo のサーバー側**で行われます（10〜20分）
- 終わるとダウンロード用のURLとQRが出るので、**スマホで開いて APK を入れる**
- 「提供元不明のアプリ」の許可を求められたら、許可する
- `eas.json` の `preview` が **APK** を作る設定です（`production` は Google Play 用の app-bundle）

**この道はまだ試していません**（この開発環境からは `expo.dev` へ通信できないため）。
うまくいかなかったら、画面の文字をそのまま貼ってください。

> **本体を直したら、APK も作り直しです。** 直すことが多いうちは上の Expo Go のほうが速く、
> **形が落ち着いてから APK** にするのが順当です。

## APIキーを焼き込む（APKでAIを使う）

> **初めての人・手順どおりに進めたい人は `docs/APKを作る手順.md` を見てください。**
> あちらが本人向けの手順書で、ここは仕組みの説明です。


APK には claude.ai の窓口（`sample`）がありません。**キーを入れないとAIはまったく動きません**
（読み取り・予定づくりはルールだけで全部動きますが、受け止めの一言も習慣の提案も出ません）。

毎回スマホで貼り付けなくて済むように、**APKを作るときに焼き込めます。**

**やることは、`APKを作る.cmd` を実行して、聞かれたら貼るだけです。**

```
APIキーを焼き込みますか？
  貼り付けて Enter … このAPKの中でAIが使えるようになります。
  何も入れずに Enter … キー無しで作ります（AIは動かず、ルールだけで動きます）。
  APIキー: ********
  保存しました（mobile\secret.json・claude）。次からは聞きません。
```

- **聞かれるのは最初の1回だけ**です。`mobile/secret.json` に残るので、2回目からは素通りします。
- **変えたい・やめたいとき**は `mobile/secret.json` を消して、もう一度実行してください（また聞かれます）。
- 提供元は**キーの見た目から決めます**（`sk-ant…` なら Claude、`AIza…` なら Gemini）。
  違っていたら `secret.json` の `provider` を直してください。

入ったかどうかは、そのあと出ます：

```
APIキーを焼き込みました: claude / ****9999
```

手で用意したいときは、`mobile/secret.example.json` を `mobile/secret.json` という名前で
コピーして `key` を貼っても同じです。環境変数 `HITOHI_AI_KEY`
（＋ `HITOHI_AI_PROVIDER` / `HITOHI_AI_MODEL`）でも動きます。
**どれも無ければ、今までと1バイトも変わりません**（何も入りません）。

### 先に知っておくこと

- **`secret.json` は git に入りません**（`.gitignore` 済み）。
  **`app/index.html` にキーを書かないこと。** あちらは git に入るので、
  一度入れると履歴に残って取り消せません。焼き込むのは**写し**（`app-html.js`）だけです。
- **APK は zip です。** 受け取った人は、展開すれば中の文字列を読めます。
  つまり **APKを人に渡すと、キーも一緒に渡ります。**
  人に配るときは `secret.json` を消してから作り直してください（決まり11）。
- **EAS のビルドはクラウドで動きます。** `secret.json` を置いて作ると、
  キーを含んだ一式が Expo のビルドサーバへ上がります。
- 提供元の管理画面で**使用上限**を決めておくと、もしもの時の被害が小さく済みます。
- 漏れたと思ったら、**提供元でそのキーを無効にして、新しいキーで作り直す**のがいちばん早いです。

### アプリ側でどう見えるか

**何も出ません。** 設定タブのAIの欄は 2026-09-21 に本人の指示でまるごと外しました
（「キーを埋め込みたい。そしてAIに関する項目ごと消したい」）。

- キーを貼る欄・モデル名の欄・「つながるか試す」「保存する」「消す」は、**どれもありません**。
- したがって **入口は焼き込みだけ**です。提供元やモデル名を変えるには、
  `mobile/secret.json` を消して `APKを作る.cmd` をやり直します。
- 動いているかどうかは、**チャットで一言打って返事が来るか**で見ます。
  呼べなかったときは、その吹き出しに理由が出ます（`Claude 401：…` のように）。
- **提供元は当てずに聞きます。** 前はキーの見た目（`AIza…` なら Gemini）で決めていて、
  実機で **Gemini のキーが Claude として焼き込まれ、全部断られました**。
  画面から入れ替える道が無い以上、ここで間違うと作り直すまで直せません。

## 何がどこまで確かめてあるか

| | 状態 |
|---|---|
| 構文（JSX を含む） | **確認済み**（`esbuild --loader=jsx`） |
| 取り込み漏れ・組み立て | **確認済み**（`expo export` が 647モジュール・2.1MB を出力） |
| QRが出るところまで走るか | **確認済み**（`expo start` が QR と `exp://…:8081` を表示） |
| スマホが受け取る中身 | **確認済み**（manifest が HTTP 200・`name: AI秘書`、bundle が HTTP 200・4,425,309バイト／775モジュール、その中に本体の文言が入っている） |
| 使っている2つが Expo Go に入っているか | **確認済み**（「追加の設定が要る」一覧に載っていない） |
| 画面が出るか | **確認済み**（2026-09-20・本人の Android。APK を入れて起動できた） |
| APK が作れるか | **確認済み**（2026-09-20・EAS で組み立て → インストール → 起動） |
| 記録が残るか | **未確認** |
| AIが動くか | **未確認** |
| 通知が鳴るか | **未確認** |

`node --check` は使わないでください。**`import` があると中身を見ずに通します**（実測）。
JSX を見るには `npx esbuild --loader=jsx < App.js` のように使います。

## 最初に確かめること（この順で）

通らないと先へ進めない順です。

1. **画面が出るか。** 出なければ `app-html.js` が無い（`node sync.js`）。
2. **記録が残るか。** 何か話しかけて、アプリを閉じて開き直す。消えていたら
   WebView が localStorage を貸していません。`App.js` の `BASE_URL` を疑うこと
   （`file://` だと貸してくれないことがあるので、実体のある出どころを与えています）。
3. **AIが動くか。** チャットで一言打って、返事が来るか見る。
   ここで初めて、殻ごしの通信が確かめられます。
   来なければ、その吹き出しに出ている理由を読むこと（設定タブに欄はもうありません）。
4. **通知が鳴るか。** 数分先に予定を入れて、アプリを閉じて待つ。
   **Android 13 以降は通知の許可が要ります**（初回に聞かれます）。

## 分かっている落とし穴

### 作り方そのものが新しくなった回は、2回実行することになる

PowerShell は**始めに台本を全部読んでから**動きます。`build-apk.ps1` は最初に `git pull` を
しますが、そこで台本が新しくなっても、**その回に動いているのは古いほう**です。
気づかないと「聞かれるはずのAPIキーを聞かれない」まま、古い手順で作ってしまいます。

いまは**自分で気づいて止まります**（「作り方そのものが新しくなりました。もう一度〜」）。
そう出たら、もう一度 `APKを作る.cmd` を実行してください。1回ぶん待つだけで済みます。

### `git pull` に失敗したら、必ず赤で出ます

前は灰色の小さい字で流していたので、**黙って古い中身の APK ができて**いました。
いまは赤で理由を出して、「それでも古いままで作りますか？」と聞きます。
`y` 以外を押せば、作らずに終わります。

### `app-html.js` は `.gitignore` に入っているのに、ちゃんと APK に入る

**実績で確かめてあります**（2026-09-20 に実機で動いた）。`.easignore` は置いていません。
もし将来 `Cannot find module './app-html'` で組み立てが落ちたら、これが原因です。
そのときは `mobile/.easignore` を作って、`app-html.js` を除外の対象から外してください。
**先回りして触らないこと**——いま動いているものを、推測で変えない。


- **`expo-notifications` を丸ごと `import` すると、Expo Go では起動前に落ちます**
  （2026-09-20・実機で報告。`[runtime not ready]: Error: expo-notifications: Android Push
  notifications … was removed from Expo Go`）。
  本体の `index.js` が `DevicePushTokenAutoRegistration.fx` を読み込み、その中で
  `addPushTokenListener(...)` を**モジュールの一番外側で**呼ぶためです。
  **プッシュを1行も使っていなくても落ちます。**
  だから `App.js` は `expo-notifications/build/…` から**要るものだけ**を直接読みます。
  **ここには「ローカル通知だけだから当たらない」と書いてありました。間違いでした。**
  使うかどうかではなく、**読み込むかどうか**で決まります。
- **通知の予約の書き方は expo-notifications の版で変わります。**
  `App.js` の `scheduleOne` が新しい形と古い形を順に試すのは、そのためです。
- **`SCHEDULE_EXACT_ALARM` は Expo Go では効きません**（`app.json` の設定は
  ビルドしたアプリにだけ効く）。Expo Go では通知が数分ずれることがあります。
- **Android は機種によってバックグラウンドを積極的に止めます。**
  通知は予約式なので影響は小さいはずですが、省電力設定の強い端末では遅れます。
- **テストは殻を見ません。** 912件は `app/index.html` の中身だけを測ります。
  殻（通知・通信・保存）は**手で確かめるしかありません**。上の4つがその手順です。

## 直すときの決まり

- **`app-html.js` を直接編集しない。** あれは写しです（git にも入れていません）。`app/index.html` を直す
- 殻に「判断」を足さない。予定の組み立ても、読み取りも、全部 `index.html` の側
- 殻を増やしたくなったら、まず「それは `index.html` 側でできないか」を考える
- **版を手で書かない。** `node_modules/expo/bundledNativeModules.json` に
  その SDK に合う版が入っているので、そこから取る
  （`npx expo install` は外部へ問い合わせるので、通らない環境がある）
