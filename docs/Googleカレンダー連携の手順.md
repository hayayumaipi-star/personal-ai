# Googleカレンダーと同期する手順

AI秘書の Android アプリと、あなたの Google カレンダー（メイン）を同期するための手順です（2026-09-27）。
**パソコンで30分ほど**かかります。やることは3つです。

1. Google Cloud で「このアプリが Google カレンダーを使ってよい」という登録をする（パソコン）
2. APK を作り直す（パソコン・10〜20分）
3. アプリの設定から「Google と同期する」を押す（スマホ）

> **この同期は、Android アプリの中でだけ動きます。**
> claude.ai の Artifact では、外へ通信できないので欄そのものが出ません。

## 同期すると何が起きるか

**Google カレンダーの「メイン」（ふだん予定を入れている、あなたの名前のカレンダー）と、このアプリの予定表が、どちらで変えてももう一方に映ります。**

| どこで | 何をすると | もう一方では |
|---|---|---|
| Google | 予定を入れる | この予定表に出る（印は「Googleカレンダー」） |
| Google | 時刻・名前を変える | ここでも変わる |
| Google | 予定を消す | ここでは「取り消し」になる（振り返りから戻せる） |
| このアプリ | 予定を話す（「明日15時から会議」） | Google のメインに入る |
| このアプリ | 時刻・名前を直す（Google から来た予定も） | Google でも変わる |
| このアプリ | 取り消す | **Google からも消える** |
| このアプリ | 完全に消す | その1件だけ Google からも消える |

- **両方で同じ予定を変えていたら、あとから変えたほう**を採ります。
- 合わせるのは、アプリを開いたとき・予定が変わった数秒後・アプリが前に出てきたとき（10分以上たっていれば）・設定の「いま合わせる」。
- 読むのは **1週間前〜2か月先** の予定です。
- **送らないもの**：アプリが提案した予定・「1日を組み立てて」で入れた枠・タスク（用事）。
- **送るのは予定の名前と日時だけ**です。Google 側の説明・場所・参加者などは、ここから書き換えません。
- 送り先は Google だけ。費用はかかりません。ログインの鍵は Android アプリの中だけに置き、アプリの画面・書き出し（JSON）には入れません。

### 本物の予定を壊さないための守り

- Google の予定を消すのは、**ここで取り消した・完全に消したとき だけ**です。アプリの「全部消す」をしても Google の予定は消しません。
- **1回に消すのは10件まで**。それより多いときは止めて知らせ、残りは次に合わせたときに消します。
- Google から予定が1件も返ってこないのに、同期している予定がいくつもある——そんな**様子がおかしいとき**は、「Google で消えた」とは読みません。
- 同期をやめても、Google の予定はそのまま残ります。

## 1. Google Cloud での登録（パソコン）

Google の画面の名前は、ときどき変わります。**見つからなければ、近い名前のものを選んでください。**
つまずいたら、画面の文言をそのまま教えてください。

### 1-1 プロジェクトを作る

1. <https://console.cloud.google.com/> を開き、**スマホで使う Google アカウント**でログインします。
2. 上のほうのプロジェクト名（または「プロジェクトを選択」）→ **「新しいプロジェクト」**。
3. 名前は「AI秘書」など何でもよいです。**「作成」**。できたら、そのプロジェクトを選びます。

### 1-2 Google Calendar API を有効にする

1. 左のメニュー（≡）→ **「API とサービス」→「ライブラリ」**。
2. 「**Google Calendar API**」を探して開き、**「有効にする」**。

### 1-3 同意画面（アプリの名前・使う人）

左のメニュー → **「API とサービス」→「OAuth 同意画面」**（または「Google Auth Platform」）。

1. **「開始」**（または「同意画面を構成」）を押し、
   - アプリ名：`AI秘書`
   - ユーザーサポートメール：自分のメールアドレス
   - 対象（ユーザーの種類）：**外部**
   - 連絡先：自分のメールアドレス
   を入れて作ります。
2. **「データアクセス」**（または「スコープ」）→ **「スコープを追加または削除」** で、次の1つにチェックを入れて保存します。
   見つからなければ、下の欄に**そのまま貼って**追加できます。
   ```
   https://www.googleapis.com/auth/calendar.events
   ```
   （＝カレンダーの予定を見て編集する。**カレンダーそのものを作る・消す・人と共有する権限は頼みません**）
3. **「対象」**（または「テストユーザー」）→ **「アプリを公開」**（「本番環境にプッシュ」）を押します。

> **なぜ公開するのか：** 「テスト」のままだと、**ログインが7日で切れて**、毎週つなぎ直すことになります。
> 公開しても、Google の審査を受けていないので、ログインのときに「Google はこのアプリを確認していません」と出ます。
> 自分で作ったアプリなので進んで大丈夫です（下の3）。
> 公開せずにテストのまま使う場合は、「テストユーザー」に自分のメールアドレスを入れてください（7日ごとに「つなぎ直す」）。

### 1-4 アプリの「指紋」（SHA-1）を調べる

Google は、**どのアプリからのログインか**を「パッケージ名」と「署名の指紋（SHA-1）」で見分けます。
指紋は、Expo（EAS）があなたの APK に付けている署名から取ります。

**やり方A（おすすめ）：Expo のサイトで見る**

1. <https://expo.dev/> にログイン → プロジェクト **hitohi** → **「Credentials」**（認証情報）→ **Android** → `star.hayayumaipi.hitohi`。
2. 「Keystore」の欄に **SHA-1 Fingerprint**（`AB:CD:…` のような文字）があるので、コピーします。

**やり方B：パソコンで調べる**

PowerShell で `mobile` フォルダに入って、次を打ちます。

```powershell
npx eas-cli@latest credentials -p android
```

「preview」を選ぶと、**SHA1 Fingerprint** が表示されます。

> **まだ一度も APK を作ったことが無い場合**、署名がまだ無いので指紋も出ません。先に一度 APK を作ってください（2の手順）。

### 1-5 Android のクライアントを作る

左のメニュー → **「API とサービス」→「認証情報」**（または「クライアント」）→ **「認証情報を作成」→「OAuth クライアント ID」**。

- アプリケーションの種類：**Android**
- 名前：何でもよい（`AI秘書 Android`）
- パッケージ名：**`star.hayayumaipi.hitohi`**（`mobile/app.json` の `android.package` と同じ。1文字でも違うと動きません）
- SHA-1 証明書フィンガープリント：1-4 でコピーしたもの

**「作成」**。出てきたクライアント ID は、**アプリに入れる必要はありません**（Google がパッケージ名と指紋で見分けます）。

## 2. APK を作り直す（パソコン）

いつもどおり `mobile/APKを作る.cmd` を実行します（Googleでログインするための部品が1つ増えたので、最初の1回は少し長くかかります）。
できた APK をスマホに入れ直してください（上書きで入ります。記録は消えません）。

## 3. アプリで同期を始める（スマホ）

1. アプリの **設定** → **「Googleカレンダー」** の欄 → **「Google と同期する」**。
2. アカウントを選びます。
3. 「**Google はこのアプリを確認していません**」と出たら → **「詳細」**（または「詳細を表示」）→ **「AI秘書（安全ではないページ）に移動」**。
   これは「Google の審査を受けていない」という意味で、あなたが自分で作ったアプリなので問題ありません。
4. 「Google カレンダーの予定の表示と編集」の許可に**チェックを入れて「続行」**。
5. 「Googleカレンダーと合わせました」と出れば完了です。スケジュールに Google の予定が出て、ここで話した予定が Google に入ります。

## つまずいたとき

| 出たもの | 理由 | 直し方 |
|---|---|---|
| 「このアプリの版では使えません」 | APK が古い（この同期を入れる前のもの） | APK を作り直す（2） |
| `DEVELOPER_ERROR` や `10` を含む文 | パッケージ名か SHA-1 が、Google Cloud の登録と合っていない | 1-4 の指紋をもう一度コピーして、1-5 のクライアントを直す（**反映に数分かかる**ことがあります） |
| 「アクセスをブロック」「access_denied」 | 同意画面が「テスト」のままで、自分がテストユーザーに入っていない | 1-3 の3（公開する）か、テストユーザーに自分を入れる |
| `Google 403` と「Calendar API has not been used」 | Calendar API を有効にしていない | 1-2 |
| `Google 403` と「insufficient」「scope」 | 許可のチェックを外して進んだ | 設定の「つなぎ直す」で、チェックを入れる |
| 「ログインが切れています」 | テストのままで7日たった／Google 側で許可を外した | 「つなぎ直す」。毎週なら 1-3 の3（公開） |
| 「消す予定が多すぎるので…止めました」 | ここで一度にたくさん取り消した | そのままで大丈夫。次に合わせたとき、残りを消します |
| 「念のため、こちらからは消していません」 | Google から予定が急にたくさん見つからなくなった | Google カレンダーを開いて、予定があるか確かめる。本当に消したなら、ここでも取り消す |

エラーの文は、設定の「最後に起きた不具合」にも残ります。**そのまま教えてもらえれば直します。**

## 確かめていないこと（正直に書いておく）

- **本物の Google とは、まだ一度も通していません**（2026-09-27 時点）。
  確かめたのは、偽の Google を相手にした中身の決まり（`tests/probe.js` の CV群・37件：読む・書く・両方向の変更・消す・守り・くり返し・送らないもの）と、
  殻が組み立てられること（Metro で APK 用に束ねられる・Google のログインの部品が入っている）まで。
- ログイン画面の出方、Google の画面の名前、最初の同期にかかる時間は、実機で見るまで分かりません。
- 同期するのは**メインのカレンダーだけ**です（家族の共有カレンダーなど、ほかのカレンダーは読みません）。
- くり返しの予定：ここで話したくり返し（「毎週月曜10時からゼミ」）は、Google のくり返しとして1件で入ります。
  **Google 側でくり返しの予定の時刻を変えても、ここには映りません**（くり返しは、ここが正）。Google でくり返しごと消したら、ここでも取り消しになります。
  Google で入れたくり返しの予定は、1回ずつの予定としてここに出ます。
- 「完了」にしても、Google の予定はそのまま残ります（Google カレンダーには「完了」がないため）。
