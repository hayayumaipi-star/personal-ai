# Google Play で配る準備

AI秘書を**ほかの人に使ってもらう**ための手順です（2026-09-28）。
自分で使う APK（`mobile/APKを作る.cmd`）とは別の道です。

## 決めたこと（本人）

| | 決めたこと |
|---|---|
| AI を使える人 | **Google でログインした誰でも** |
| 1人が1日に AI を使える回数 | **40回**（サーバーの `DAILY_LIMIT`） |
| 配り方 | **Google Play** |
| Gemini の枠（無料か有料か） | **保留**。いまは無料のつもりで作ってある（下の 4） |

## 全体の形

```
スマホ（配る版のアプリ）
  ├─ 記録（話したこと・予定・わたしのこと）… スマホの中だけ。どこにも送らない
  ├─ AI を使うとき ─→ 中継サーバー（Cloudflare・あなたが立てる）─→ Gemini
  │                     ・Google でログインした人か確かめる
  │                     ・1人1日40回まで数える（中身は残さない）
  │                     ・Gemini のキーはここだけが持つ
  └─ Googleカレンダー（選んだ人だけ）─→ Google に直接（サーバーを通らない）
```

- **配るアプリには APIキーが入っていません。** 入れると、アプリを分解した人に取られるからです。
- ログインしない人も使えます。そのときは AI なしで、**ルールだけで読み取ります**（アプリの機能はほぼ全部動く）。
- アプリの画面には、**何を・どこへ送るか、無料の枠なら Google が中身を読むことがあること**を、ログインする前に出します。

やることは3つの場所にまたがります。**この順で**進めてください（あとの手順が、前の手順で出てくる文字を使います）。

1. **Cloudflare** … 中継サーバーを立てる（パソコン・30分）
2. **Google Cloud** … ログインの登録（パソコン・30分）
3. **Google Play Console** … アプリを出す（登録25ドル・審査と14日のテストがある）

---

## 0. 先に知っておくこと

- **同じスマホに「自分用の APK」と「Play の版」は同時に入りません。** 名前（`star.hayayumaipi.hitohi`）が同じで、署名が違うためです。
  Play の版に移るときは、**先に自分用で「設定 → データ → 持ち出す」で記録を控え**、自分用を消してから Play の版を入れて「持ち込む」。
  （記録はスマホの中にしか無いので、控えずに消すと戻せません）
- **配る国は、まず日本だけ**にしてください。Gemini の利用規約で、**ヨーロッパ（EEA）・スイス・イギリスの人に使わせるなら有料の枠しか使えない**と決まっています。
- `mobile/play.json`（サーバーの場所など）と `mobile/secret.json`（自分用のキー）は git に入りません。**どちらも人に渡さないでください。**

## 1. 中継サーバーを立てる（Cloudflare）

無料の範囲で動きます（1日10万回まで。1人40回なら2,500人ぶん）。

### 1-1 アカウント

<https://dash.cloudflare.com/sign-up> で無料のアカウントを作ります（メールアドレスで可）。

### 1-2 パソコンからログイン

PowerShell で、このリポジトリの `server` フォルダに入って：

```powershell
cd server
npx wrangler@latest login
```

ブラウザが開くので「Allow（許可）」。

### 1-3 回数を数える場所（D1）を作る

```powershell
npx wrangler@latest d1 create hitohi-usage
```

出てきた `database_id = "…"` の `…` を、`server/wrangler.toml` の `database_id = "ここにデータベースID"` に貼ります。つづけて：

```powershell
npx wrangler@latest d1 execute hitohi-usage --remote --file=schema.sql
```

（中にできるのは「だれか（元に戻せない形）・日付・回数」の表だけです）

### 1-4 Gemini のキーを入れる

<https://aistudio.google.com/apikey> でキーを作り（自分用とは**別のキー**がおすすめ。止めるときに自分用を巻き込まない）：

```powershell
npx wrangler@latest secret put GEMINI_KEY
```

聞かれたらキーを貼って Enter。**キーはファイルには書きません**（Cloudflare の中にだけ入る）。

### 1-5 `wrangler.toml` の残り

- `CONTACT_EMAIL` … 問い合わせ先のメールアドレス（プライバシーポリシーに出ます。**公開されます**。配る用のアドレスを作るのがおすすめ）
- `GOOGLE_CLIENT_ID` … **2-3 で作ってから**入れます。いまは空けておいて、先に 1-6 へ進んでかまいません

### 1-6 出す

```powershell
npx wrangler@latest deploy
```

最後に `https://hitohi-ai.○○.workers.dev` のような URL が出ます。**これが「中継サーバーの場所」です**（あとで2回使う）。

確かめ方（ブラウザで開く）：

| 開くところ | 出れば正しいもの |
|---|---|
| `https://…workers.dev/` | 「AI秘書 のサーバーです。」 |
| `https://…workers.dev/privacy` | プライバシーポリシー（Play に出す URL） |
| `https://…workers.dev/v1/status` | `login_required`（ログインしていないので断られる＝正しい） |

## 2. Google Cloud（ログインの登録）

Google の画面の名前は、ときどき変わります。**見つからなければ、近い名前のものを選んでください**（Play Console も同じ）。

Googleカレンダー連携で作ったプロジェクト（`docs/Googleカレンダー連携の手順.md` の 1）を**そのまま使えます**。まだなら、あちらの 1-1〜1-3 を先に。

### 2-1 同意画面に、プライバシーポリシーを入れる

「Google Auth Platform」（または「OAuth 同意画面」）→「ブランディング」：

- アプリのホームページ・プライバシーポリシーのリンク：`https://…workers.dev/privacy`
- 承認済みドメイン：`workers.dev` の場所は入れられないことがあります（下の 2-5）

### 2-2 同意画面の「対象」

「外部」「本番環境」（公開）にします。テストのままだと、**テストユーザーに入れた人しかログインできません**。

### 2-3 ウェブのクライアント ID を作る（★ 2か所に貼る）

「クライアント」→「クライアントを作成」→ 種類：**ウェブ アプリケーション**（名前は何でも。URL の欄は空でよい）。

出てきた `○○.apps.googleusercontent.com` を：

1. `server/wrangler.toml` の `GOOGLE_CLIENT_ID` に貼って、もう一度 `npx wrangler@latest deploy`
2. あとで `Playに出す.cmd` に聞かれたら貼る（3-3）

> **これは「宛先」です。** アプリが Google から受け取るログインの証明には宛先が書いてあり、サーバーは**宛先がこれと同じものだけ**を通します。
> Android のクライアント ID ではありません。

### 2-4 Android のクライアント ID（Play の署名で）

Play から入れたアプリは、**Google が付け直した署名**で動きます。その指紋を登録しないと、ログインが `DEVELOPER_ERROR` で止まります。

1. 3-3 で AAB を一度上げたあと、Play Console →（アプリ）→「テストとリリース」→「アプリの完全性」→「アプリの署名」で、
   **「アプリ署名鍵の証明書」の SHA-1** をコピー。
2. Google Cloud →「クライアントを作成」→ 種類：**Android**・パッケージ名 `star.hayayumaipi.hitohi`・SHA-1：いまのもの。

自分用 APK のための Android クライアント（Expo の署名の SHA-1）は、そのまま残してください。**両方あって大丈夫です**。

### 2-5 Google の確認（審査）について

- Googleカレンダーの権限（`calendar.events`）は Google が「**機密性の高い権限**」と呼ぶもので、確認を受けていないと：
  ① ログインのときに「Google はこのアプリを確認していません」と出る ② **この権限を許可できる人が100人まで**。
- 確認を受けるには、プライバシーポリシーを**自分が持っていると証明できるドメイン**に置く必要があります。
  `workers.dev` で通るかは分かりません。**自分のドメイン（年に千数百円）を1つ持つのが確実**です
  （Cloudflare で買えば、中継サーバーにそのままつなげられます）。
- **AI のためのログイン（名前・メールアドレス）は、機密ではない基本の権限**なので、この制限は受けません。
  カレンダーの同期を選んだ人にだけ、あとから権限を頼む作りにしてあります。

## 3. Google Play Console

### 3-1 デベロッパー登録

<https://play.google.com/console/signup> — **25ドル（1回だけ）**・本人確認（身分証）があります。「個人」で登録します。

> 2023年11月13日より後に作った個人のアカウントは、**製品版に出す前に「12人以上が14日間続けて参加したクローズドテスト」が要ります**。
> 家族や友だちに Google アカウントで参加してもらう形です（アプリを入れて、14日間抜けないでもらう）。

### 3-2 アプリを作る

「アプリを作成」→ 名前「AI秘書」・言語 日本語・アプリ・無料。

### 3-3 AAB を作って上げる

パソコンで **`mobile/Playに出す.cmd`** を実行します（中身は `APKを作る.cmd` と同じ流れで、AAB を作る）。
最初の1回だけ、2つ聞かれます：

```
  ① 中継サーバーの場所（npx wrangler deploy のあとに出た https://… の URL）
  ② ウェブのクライアント ID（2-3 で作ったもの）
```

`mobile/play.json` に残るので、次からは聞かれません。**APIキーは聞かれません**（入れない版です。`secret.json` があっても入れません）。

10〜20分で AAB のダウンロード URL が出ます。**AAB はスマホに直接は入れられません。**
Play Console →「テスト」→「内部テスト」（まず自分だけ）→ 新しいリリース → AAB を上げる。
上げたら **2-4**（署名の SHA-1）へ。

### 3-4 ストアに出すための記入

Play Console の「アプリのコンテンツ」で聞かれるもの。**分かっている事実**を書いておきます（答えは本人が選ぶ）：

| 聞かれること | このアプリの事実 |
|---|---|
| プライバシーポリシー | `https://…workers.dev/privacy` |
| 広告 | 無し |
| アプリのアクセス権（審査の人がどう入るか） | ログイン無しで全部開ける。AI は Google でログインすれば誰でも使える（審査用のアカウントは要らない） |
| 対象年齢 | 子ども向けではない（13歳以上など） |
| データ セーフティ：集めるデータ | AI を使うとき、**話した内容**と、読み取りに要る**予定・体調の申告・わたしのことの短い文**が、中継サーバーを通って Google（Gemini）へ送られる。**無料の枠では Google が改善に使う**ので「第三者と共有」にあたる可能性が高い。中継サーバーは中身を保存しない。記録そのものはスマホの中だけ |
| データ セーフティ：暗号化 | 通信はすべて HTTPS |
| データ セーフティ：削除 | 記録はアプリの「記録を消す」かアプリの削除で消える。サーバーの回数の記録は2日で自動で消える |
| 正確なアラーム（`SCHEDULE_EXACT_ALARM`） | 予定の時刻に通知するため（カレンダーの用途）。申告を求められたらそう書く |
| コンテンツのレーティング | 質問票に答える（暴力などは無し。AI の返事がある＝利用者どうしのやりとりは無し） |

### 3-5 クローズドテスト → 製品版

「テスト」→「クローズド テスト」にリリースを作り、テスターのメール（または Google グループ）を入れて、参加用のリンクを送ります。
12人以上が14日間続けて参加したら、ダッシュボードの「製品版へのアクセスを申請」。

## 4. Gemini の枠（保留中）

| | 無料の枠（いま） | 有料の枠 |
|---|---|---|
| 中身の扱い | **Google が製品の改善に使い、担当者が読むことがある** | 改善に使わない |
| 使える国 | 日本など（**ヨーロッパ・スイス・イギリスには出せない**） | どこでも |
| 1日の上限 | キー全体に上限があり、**全員で分け合う**（超えると、その日は誰も AI を使えない＝アプリは「混み合っている」と言ってルールだけで読む） | 支払った分だけ |
| 費用 | 0円 | 使った分（1回あたり、ごくわずか） |

**有料に切り替えるとき**は、Google AI Studio で支払いを設定したうえで、`server/wrangler.toml` の `GEMINI_TIER = "paid"` にして `npx wrangler@latest deploy`。
**アプリを作り直す必要はありません。** 画面の注意書き（「無料の枠を使っているため…」）と、プライバシーポリシーの文が、サーバーの設定を見て自動で切り替わります。

## 6. まだ足りないもの・確かめていないこと（正直に）

### 足りないもの（Play の決まりで求められる可能性が高い）

- **AI が作った文を、アプリの中から報告できる仕組み。** Google Play は、生成 AI の文を出すアプリに
  「不快な AI の出力を、アプリの中で報告・通報できること」を求めています（AI 生成コンテンツのポリシー）。
  このアプリの AI は「受け止めの一言」と「習慣の提案」を書くので、**当てはまると考えてください**。**まだ作っていません。**
  報告をどこへ届けるか（サーバーに残す／メールで送る）で、プライバシーポリシーも変わるので、**本人が決めてから作ります**。

### 確かめていないこと

- **本物の中継サーバー・本物の Google・本物の Play とは、まだ一度も通していません**（2026-09-28 時点）。確かめたのは：
  - サーバーの中身（`server/test.mjs`・46件）：本物の署名（RSA）で作った偽の Google の証明、本物の SQL（Node の SQLite）で数える、偽の Gemini。
  - アプリの中身（`tests/probe.js` の CW群・31件）：偽の殻で、ログイン前・ログイン・使い切り・ログインが切れた・ログアウト・カレンダーとの関係。
  - 殻が組み立てられること（`npx expo export`）と、`Playに出す.cmd` の流れ（偽の道具で通した）。
- Google のログインで **ID トークン（証明）が本当にもらえるか**は、ウェブのクライアント ID を入れた AAB を実機で動かすまで分かりません。
- Play の審査で何を言われるか。

## つまずいたとき

| 出たもの | 理由 | 直し方 |
|---|---|---|
| アプリで「AIを使うには…ログインしてください」が消えない | ログインの証明をサーバーが通していない | `wrangler.toml` の `GOOGLE_CLIENT_ID` が 2-3 のウェブのクライアント ID と同じか・入れたあと deploy したか |
| ログインで `DEVELOPER_ERROR` | Play の署名の SHA-1 が Google Cloud に無い | 2-4 |
| 「今日のAIの回数を使い切りました」 | その人が今日40回使った | 日本時間の0時に戻る。回数は `DAILY_LIMIT` |
| 「混み合っているので、ルールだけで読み取りました」が続く | Gemini のキー全体の上限に届いた（無料の枠） | 次の日を待つか、有料の枠へ（4）。**向こうの都合で失敗した回は、その人の回数に数えません** |
| `Playに出す.cmd` が「play.json に key を書かないで」で止まる | 配る版にキーを入れようとしている | `mobile/play.json` から `key` の行を消す |
