# これからの開発計画（2026-09-26）

`docs/残タスク.md`（2026-09-20）の続き。あれは「何が足りないか」の一覧で、
これは **「どの順番でやるか」と「何を決めてもらう必要があるか」** を書いたもの。

## いまの位置

| | 状態 |
|---|---|
| 話す → 予定とタスクになる（アプリの本体） | **できている。** テスト 1,176件。読み取りの穴は、実機の報告のたびに塞いできた |
| 画面（UI・UX） | **完成版として整えた**（2026-09-26・決まり15l） |
| Android アプリ（本物） | **動いている。** 本人が毎日使い、実機の報告が届いている |
| **記録が消えないこと** | **確かめていない。** 残タスクの 0-1〜0-4 が「未確認」のまま |
| **直したものがスマホに届くまで** | **10〜20分の作り直しが毎回要る** |
| 構想の7つの目標 | 「タスク化→予定化」と「覚える」は動く。**観測・向こうから声をかける・生活全体**は止まったまま |

**いちばん大きな変化**：前の計画（`docs/構想と現在地.md`）は「ブラウザのタブを開いている間しか
存在しない」ことを、観測・声かけが止まっている理由にしていた。
**いまは Android アプリがある。** 閉じていても通知が鳴り、端末の機能（歩数・睡眠・マイク）に
手が届く場所に立っている。止まっていた目標の扉が、半分開いた。

ただし **土台（記録が消えない・直したものがすぐ届く）が固まっていない。**
その上に機能を積むと、積んだものごと失う危険がある。だから順番はこうなる：

```
段階0  確かめる      … 記録は残るか・通知は鳴るか（本人が実機で・半日）
段階1  失わない      … 端末にファイルで控えを残す。Artifact の記録を移す
段階2  すぐ届く      … 作り直さずに、直したものをスマホへ届ける
段階3  使いながら直す … 2週間ふつうに使い、出てきた読み違いを直す
段階4  広げる        … APKだからできること（朝夜の声かけ・音声・歩数と睡眠）
段階5  人に渡す      … 誰でも使える形にする
```

**段階0〜2 は小さい**（どれも殻と本体に少し足すだけ）。**段階4 から先が大きい。**

## 段階0　確かめる（本人が実機で・半日）

作るものは無い。**残タスクの 0-1〜0-4 を埋める**だけ。ここが駄目なら、あとの計画が全部変わる。

| # | やること | 駄目だったら |
|---|---|---|
| 0-1 | 何か話す → アプリを**完全に終了**（最近のアプリ一覧から払う）→ 開き直す。記録は残っているか | 段階1 を最優先で、殻側の保存に切り替える |
| 0-2 | 設定 → 書き出す。文字がコピーできるか | 段階1 の「ファイルで控え」を先に |
| 0-3 | 設定 → 読み込む。ファイルを選ぶ画面が出るか | Artifact からの移行は段階1 の殻の仕事になる |
| 0-4 | 5分後の予定を入れて、アプリを閉じる。通知は鳴るか。「完了」を押すと完了になるか | 殻の通知まわりを直す |
| 0-5 | 端末の設定で文字を大きくしたとき、アプリの文字も大きくなるか（決まり15h・未確認） | 殻で WebView の文字設定を渡す |
| 0-6 | 端末の「戻る」ボタンで、開いたシートだけが閉じるか（完成版の穴・未確認） | 殻で戻るボタンを受け取る |
| 0-7 | **APKを作り直して入れ直したとき**、記録が残るか | 作り直しのたびに消えるなら、段階1・2 が最優先 |

**0-7 は今まで表に無かった。** 更新のたびに作り直す運用なので、ここが消えるなら毎回全部消える。

## 段階1　失わない

**いまの記録は、端末の中の1か所（`localStorage`）にしか無い。**
控えは「文字をコピーするだけ」で、300KBをスマホでコピペするのは現実的ではない（残タスク 1-1）。
端末をなくす・アプリを消す・保存の上限に当たる——どれでも全部消える。

| やること | 中身 | 大きさ |
|---|---|---|
| **1-a. 書き出しを、ファイルにする** | 殻が `expo-sharing` で「共有」の画面を出す。Google ドライブ・メール・ファイルに保存できる | 小（依存 +2：`expo-file-system` / `expo-sharing`。殻の仕事「運ぶ」の範囲） |
| **1-b. 読み込みを、ファイルから** | 0-3 が通らなければ、殻が `expo-document-picker` で選ばせる | 小（依存 +1） |
| **1-c. Artifact の記録を移す** | Artifact（PC）で書き出す → ドライブ経由でスマホへ → 読み込む。読み込みは「足すだけ・二重に入れない」ので安全（完成版の穴 A5） | 作るものは無い。**移すかどうかは本人が決める**（下の決めごと1） |
| **1-d. 保存の上限を測る** | WebView の `localStorage` には上限がある（**端末ごとに違い、まだ測っていない**）。いまの記録の大きさと上限を設定タブで比べ、近づいたら知らせる | 小 |
| 1-e. （任意）ときどき自動で控え | 週1回、アプリを開いたときに端末へ控えを書く | 小。1-a ができれば足せる |

**使う部品は、いまの Expo（SDK 57）に全部そろっている**（`bundledNativeModules.json` で確認済み）。

## 段階2　すぐ届く

**いまは1か所直すたびに、APKの作り直し（10〜20分）と入れ直しが要る。**
残タスク 1-3「どこまで溜めてから作り直すか」が決まらないのは、これが重いから。

**案：`expo-updates`（EAS Update）を入れる。**
一度だけ作り直せば、あとは直したもの（`index.html` の中身）が**数分でスマホへ届く**。
アプリを開いたときに新しい版を取りに行き、次に開いたときから新しくなる。

| よい点 | 代償 |
|---|---|
| 決まり5 の④（作り直し）が、ほとんど要らなくなる | 依存が1つ増える（決まり14 の「殻は薄く」との相談） |
| 実機の報告 → 直す → その日のうちに届く、が回る | 届ける中身は Expo のクラウドを通る。**焼き込んだキーも一緒に通る**（いまの EAS Build と同じ条件。新しい危険ではない） |
| 1-3 の決めごとが要らなくなる | 殻そのもの（通知・通信）を直したときは、今までどおり作り直しが要る |

**決めてもらうこと2** を見て、入れるかどうかを決める。

## 段階3　使いながら直す（2週間）

新しい機能は足さない。ふつうに使って、**「思ったのと違う」を見つけたらそのまま伝えてもらう。**
ここ1週間の直しは、ほとんどが実機の報告から来ている。そのやり方がいちばん当たる。

いま分かっている候補（報告が来たら先にやる）：
- 1行に予定を2つ言う（「9時に歯医者。そのあと11時から会議。」）と、1件になる（完成版の穴・最後の行）。
  いまは黙らずに知らせる（決まり4l）が、**入らないことは変わっていない。**
- AIの1日の回数。Gemini の無料枠で1日500回、1回話すと2回呼ぶ（決まり7b・13d）。
  **1日250回話すと止まる。** 足りているかは使ってみないと分からない。

## 段階4　広げる（APKだからできること）

**安く、プライバシーの負担が小さい順に並べた。** 上から1つずつ。

| # | 何ができるようになるか | 構想の目標 | 大きさ | 気をつけること |
|---|---|---|---|---|
| **4-a. 朝と夜の声かけ** | 朝8時に「今日の案」、夜に「今日やったこと」を通知で出す。押すと、その画面が開く | #6 向こうから声をかける | **小**。いまの通知の予約を使うだけ | 時刻は本人が決める。**考えるのはアプリを開いたとき**（閉じている間は考えない） |
| **4-b. アプリの中の音声入力** | マイクのボタンを押して話す | 入力を軽くする | 中。**WebView の中では音声認識が使えない**ので、殻の仕事になる | いまは端末のキーボードの音声入力で代わりになっている。**要るかどうかを先に聞く** |
| **4-c. 歩数と睡眠を読む**（Health Connect） | 「昨日は5時間しか寝ていない」を、本人が言わなくても分かる | #1 観測・#5 生活全体 | 大。殻に Health Connect をつなぐ。Android の許可画面が要る | **点数にしない**（決まり3）。「睡眠5時間」という事実だけを持ち、「疲労度」は作らない |
| 4-d. 使ったアプリの時間を読む | 「研究計画書を35分」→「『研究計画書を書く』を進めた？」 | #1 観測・#4 行動→意図 | 大。Android の使用状況の許可が要る | **いちばん見られたくない情報**。4-c の様子を見てから決める |
| 4-e. 閉じている間も考える | 夜のうちに翌日の案を組んでおく | #6 | 大。Android は裏の処理を機種ごとに止める。決まり14「定時に起きる仕組みは入れない」を見直すことになる | 残タスク 3 の3案のうち、いまは「通知だけで良しとする」を勧める。4-a で足りるかを見てから |

**4-a を最初に勧める理由**：常駐（残タスク 3）で本当に欲しかったのは「向こうから声をかける」ことで、
それは**予約した通知で半分できる**。考える処理を裏で動かさなくても、
「開いて」と声をかけて、開いた瞬間に考えれば間に合う。

## 段階5　人に渡す（目標C：誰でも使える）

いまの作りは **本人のキーを焼き込んだAPK** で、渡すと**本人の枠で使われる**（決まり13c の代償）。
誰でも使える形にするには：

| やること | 中身 |
|---|---|
| 5-a. キーを入れる入口 | 焼き込みが無いAPKだけ、最初の起動で「AIのキーを入れる」を出す。入れたキーは端末の中だけ（`db` にも書き出しにも入れない・決まり13） |
| 5-b. 最初の3分 | 初めて開いた人が、何を話せばいいか分かる案内（いまは「例を入れてみる」だけ） |
| 5-c. 配り方 | APK をそのまま渡す（`docs/友達に渡す.md`）か、Google Play に出すか |

**5-a は決まり13c（AIの欄はまるごと外す）を部分的に戻すことになる。** 本人に聞いてから。

## 目指す形：ジャービス（2026-09-26・本人の言葉）

本人の言葉：**「アイアンマンのジャービスのようなものにしたい」**。

> **同じ日に却下**（本人の言葉「あまり魅力的に感じなかったので却下」）。
> 下の表は、こちらが「ジャービス」を7つに分けて出した案で、**本人が選んだ方向ではない**。
> 次のセッションは、ここを進める前提にしないこと。記録として残す。

ジャービスがしていることを7つに分けて、いまのアプリと並べた。

| ジャービスがすること | いまのAI秘書 | 足りないもの | 道 | 大きさ |
|---|---|---|---|---|
| **声で答える** | 文字だけ | 返事を読み上げる | 殻に `expo-speech`（Expo に同梱・SDK 57 で確認済み） | 小 |
| **声で話しかけられる** | キーボードの音声入力で代わりにしている | アプリの中のマイクボタン | 殻に音声認識。**Expo 本体には無く、外の部品が要る（要調査）** | 中 |
| **呼ばなくても声をかける** | 予約した通知だけ | 朝の「今日の案」・予定の前の一言・夜のふりかえり | 段階4-a。読み上げと組み合わせる | 小 |
| **人柄がある** | 短く軽い返事（決まり6d） | 話し方を決める（丁寧な執事か、今の口調か） | 依頼文を変えるだけ。**口調は本人が決める** | 小 |
| **代わりにやる** | 予定表を組むだけ | アラームを掛ける・地図を開く・電話をかける | 殻が Android の機能を呼ぶ（「運ぶ」仕事の範囲） | 中 |
| **状況を知っている** | 本人が話したことだけ | 歩数・睡眠・使ったアプリ | 段階4-c・4-d | 大 |
| **いつも動いている** | 開いたときだけ考える | 閉じている間も考える | 段階4-e | 大 |

**勧める順番**：読み上げ → 人柄 → 声かけ → マイク → 代わりにやる → 状況を知る。
**最初の3つは小さい。それでいちばんジャービスらしくなる。** 声で答えて、呼ばなくても話しかけてくる。

**土台（段階0〜2）は先に要る。** 読み上げもマイクも殻の部品なので、足すたびに APK の作り直しが要る。
段階1・2 と同じ1回の作り直しにまとめれば、手間は1回で済む。

**ジャービスでも変えないこと**：
- **点数を作らない**（決まり3）。「疲労度 72%」とは言わない。「昨日は5時間しか寝ていません」とは言う。
- **いつも耳を澄ませている形（呼びかけの言葉で起きる）はやらない。** 電池を食い、ずっとマイクが開いている。
  マイクはボタンを押したときだけ開く。
- **勝手に実行しない。** アラームを掛ける・電話をかけるは、押して確かめてから（決まり2「推測を確定にしない」）。
- **記録は端末から出さない。** 送るのは今までどおり、AIに読ませる分だけ。

## 決めてもらうこと

急ぐ順。**段階0 の結果を見てから決めてよいもの**もある。

| # | 決めること | 選べる道 | こちらの勧め |
|---|---|---|---|
| **1** | Artifact にある過去の記録を、スマホへ移すか | 移す（段階1-c）／移さず、Artifact に置いたまま | **移す。** 読み込みは「足すだけ」なので、失敗しても今の記録は消えない |
| **2** | `expo-updates` を入れるか（段階2） | 入れる／入れず、溜めてから作り直す | **入れる。** 実機の報告から直すやり方が、いちばん当たっているから |
| 3 | 常駐をどうするか（残タスク 3） | 通知だけ（4-a）／裏で動かす／サーバーを借りる | **通知だけ**で始める。足りなければ、そのとき考える |
| 4 | 観測をどこまでやるか | 歩数と睡眠まで（4-c）／使ったアプリまで（4-d）／やらない | まず 4-c だけ。4-d は様子を見てから |
| 5 | 人に配る日が来たら、キーの入口を戻すか（段階5） | 戻す／本人専用のままにする | 配る予定が決まってから |
| 6 | Artifact を共有したままにするか | いまは公開の結果に「自分だけが開ける」と出ている | 本人が決める（決めたら、設定タブの文と CLAUDE.md をそろえる） |

## この計画で変えないこと

- **タブは4つ。** 新しい機能も、いまのタブの中に入れる。
- **殻にロジックを入れない**（決まり14）。殻が足すのは「運ぶ」仕事だけ（ファイル・更新・通知・端末のデータ）。
- **点数を作らない**（決まり3）。観測したものは事実のまま持つ。
- **本人の生活データをリポジトリに入れない。** 観測したものも、端末の中だけ。
- **1つ足すたびに、テスト4つ → push → 公開 →（段階2 までは）APK。** 決まり5 のまま。
