## 既知の弱点

1. **AIをオフにすると、言い直しと完了の自動判定ができない。** ルールでは
   「15時じゃなくて14時」がどの予定を指すか決められないため。黙って無視はせず、
   「AIをオンにするか、ボタンから直して」と返す。完了だけは、見出しの漢字・カタカナ語が
   発話に含まれ、候補がちょうど1件のときに限り自動で判定する。
2. **抽出は日本語のルールベースなので取りこぼす。** 特に、丁寧語の長文、1行に複数の用件、
   比喩表現。→ AIオンで補える。→ 根本対策は「よく取りこぼす言い回し」を
   `tests/harness.js` にケースとして足してから正規表現を直すこと。
3. **1行に2つのタスクがあると1つにまとめてしまう。** 1行＝1話題の前提を置いたため。
   改行で分ければ回避できる。
4. **AIオンのとき、発話のたびに「いま開いている用事の一覧」も送っている。** 言い直しを
   既存の項目に結びつけるために必要だが、送信量は発話単体より多い。設定で止められる。
5. **AIオンだと返事に数十秒かかる。** `modelTier` が `"default"`（考えてから書く）のため。
   速度を優先するなら `"quick"` に変えられるが、言い直しの取り違えが増える。
3. **作業枠の並べ方が単純。** 期限の近さ順に前から詰めるだけ。集中しやすい時間帯や
   休憩の挿入は考慮していない。
4. **保存件数の上限がある。** claude.ai 側のデータベースは1ページあたり5,000件まで。
   メモと項目の合計。1日20件としても半年以上もつが、いずれ古い記録の整理が要る。
5. **文字起こしの話者分離をしていない。** 会議の録音をそのまま入れると他人の発言も
   自分のタスクとして読み取る可能性がある。

## 次に足すべきもの（推奨順）

### 1. 朝と夜の振り返り（実装しやすく、効果が大きい）
- 朝: その日の案を開いたときに「昨日やり残したもの」を先に見せる。
- 夜: 「今日どうだった？」の1行入力 → `condition` として記録。
- なぜ最初か: 新しい外部連携が不要で、**「継続的に理解する」の芯**がここで立ち上がるため。

### 2. 目標と週の視点
- `goal` を今は記録するだけ。「今週この目標に何分使ったか」を出す。
- 週表示（7日分のタイムライン）を足す。
- なぜ: 「次の行動」だけだと目先の作業に寄る。目標との接続がこのプロジェクトの主旨。

### 3. カレンダー取り込み（ファイル経由から）
- まず `.ics` ファイルの読み込みだけ実装する。Googleカレンダーは「設定 → エクスポート」で
  `.ics` を出せる。**認証不要で、外部送信も発生しない。**
- 本物のカレンダーへの書き込みは、その次。**実行前に必ず確認を取る設計にすること。**

### 4. 音声の取り込み
- Androidのキーボード音声入力で足りるか、まず1週間使って判断する。
- 足りなければ、ブラウザの音声認識（Web Speech API）を検討。Android Chromeで動くが、
  **音声がGoogleのサーバーに送られる**点を画面に明記すること。

### 5. 健康データ（Android）
- Health Connect からの直接読み取りはブラウザからはできない。
- 現実解: Health Connect 対応アプリでCSVを書き出し、それをファイル取込する。
- **睡眠時間などの数値は、必ず「測定値（出典：Health Connect）」として、
  本人の主観申告と別のフィールドに入れること。** 混ぜると設計が壊れる。

### 6. 常時稼働（ここで初めて設計の分岐が来る）
選択肢は3つ。**まだ決めなくていい。** 1〜5をやってから判断してください。

| 案 | 中身 | 費用 | 向き不向き |
|---|---|---|---|
| このPCで動かす | Python等で常駐プログラム | 0円 | PCの電源が入っている間だけ。外出先では動かない |
| 小さなサーバーを借りる | 月数百円のVPS等 | 月300〜1,000円程度 | 24時間動く。設定の手間と、データを預ける判断が要る |
| 定期実行だけ任せる | 決まった時刻に処理を走らせる仕組み | 0円〜 | 「朝7時に今日の案を作る」程度なら足りる |

**Claude Code を閉じたあと何が動くか**: 現時点では **何も動きません**。
「AI秘書」はブラウザで開いたときだけ動くページです。Claude Code はこのファイルを
書き換えて公開するための道具であって、常駐サービスではありません。

### 7. 完全ローカル版への切り替え（データを1バイトも外に出したくなったら）
- このPCに Python を入れ、同じデータ構造で SQLite に保存するローカルサーバーを作る。
- スマホからは同じWi-Fi内でブラウザから開く。
- 現在の「書き出す（JSON）」がそのまま移行データになるよう、構造を揃えてあります。
- 判断材料: 外出先で使えなくなる／PCの電源が要る／設定の手間、と引き換えです。
- **ローカル推論（AIの読み取りを手元で動かす）を入れるとしたら、切り替えるのはこのときです。**
  いまは Artifact の CSP でモデルの重みを取りに行けないので、置き場所を変えない限り実現しません。
  調査の結果と出典は `docs/ローカルAI調査.md`（2026-09-12）。

## 友達と作る場合

**手順は `docs/友達に渡す.md` にまとめました**（2026-09-13）。要点だけ：

- 渡し方は2つ。**A: `app/index.html` を渡す**（相手が自分のページとして公開する）／
  **B: リンクを共有する**（開発中の、いまのやり方）。
- **A なら、データもAIの利用枠も完全に分かれます。** 生活データ（書き出したJSON）は渡さない。
- **B では、リンクを開いた相手に本人の記録がそのまま見えます。** 記録が共有の場所に
  入っているためで、隠す設定はありません（2026-09-13 に実機で確認）。
  だから **共有している間は、見られて困るものを入れない**——これが条件です。
- **Git は導入済み**（2026-09-13・`git 2.55.0`）。GitHub にも上げてあります
  （`hayayumaipi-star/personal-ai`・**非公開**）。`docs/開発メモ.md` 参照。
