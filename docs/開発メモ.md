## Windows 以外で走らせるとき（Linux ＋ Chromium）

**2026-09-13、Claude Code の Linux セッションで4つとも走らせて確認しました。**
Edge が無くても、Chromium 系が入っていれば **引数はそのまま代用できます**。
違うのは実行ファイルの場所と、HTMLの組み立て方（PowerShell ではなく `cat`）だけです。

```bash
cd ~/personal-ai
S=/tmp/hitohi-test                 # 生成物の置き場。リポジトリの外に置くこと
mkdir -p "$S"
CHROME=/opt/pw-browsers/chromium-1194/chrome-linux/chrome   # 場所は環境による

# 受け入れ（harness）・通し（scenario）・境界（probe）は同じ形で組み立てる
{ echo '<!doctype html><html><head><meta charset="utf-8"></head><body>'
  cat app/index.html
  echo '<script>'; cat tests/harness.js; echo '</script></body></html>'
} > "$S/run.html"

"$CHROME" --headless=new --disable-gpu --no-sandbox --no-first-run \
  --force-prefers-reduced-motion \
  --user-data-dir="$S/prof" --allow-file-access-from-files \
  --virtual-time-budget=30000 --dump-dom "file://$S/run.html" 2>/dev/null \
  | grep -o '合計 [0-9]* 件 / 失敗 [0-9]* 件'
```

`scenario.js` / `probe.js` は、上の `harness.js` を差し替えるだけです。
`walkthrough.js` だけは `mock-claude.js` を **本体より前** に入れ、窓幅を指定します。

```bash
{ echo '<!doctype html><html><head><meta charset="utf-8"></head><body><script>'
  cat tests/mock-claude.js; echo '</script>'
  cat app/index.html
  echo '<script>'; cat tests/walkthrough.js; echo '</script></body></html>'
} > "$S/run-walk.html"

"$CHROME" --headless=new --disable-gpu --no-sandbox --no-first-run \
  --force-prefers-reduced-motion \
  --user-data-dir="$S/profw" --allow-file-access-from-files \
  --virtual-time-budget=90000 --window-size=477,900 \
  --dump-dom "file://$S/run-walk.html" 2>/dev/null \
  | grep -o '合計 [0-9]* 操作 / 失敗 [0-9]* 件'
```

> **`--virtual-time-budget` は 90000 にすること**（2026-09-24）。
> 45000／60000 では、**14回に1回ほど「ファイルから資料を渡す」だけが落ちる**。
> 仮想時計は実際の入出力より先へ走るので、ファイルの読み取りが返る前に持ち時間が尽きる。
> ずっと「まれに落ちる1件」と書いてきたものの正体はこれで、**本体の不具合ではない**。
> 90000 にして12回・14回と流して、1件も落ちないことを確かめてある。
> 待つ側（`tests/walkthrough.js`）も3秒から30秒へ伸ばした。入った瞬間に返るので、ふだんは遅くならない。

### `--force-prefers-reduced-motion` を必ず付けること

付けないと `probe.js` の W群 `.btn.pri の文字が読める（dark）` が **2.80** で落ちます。
**アプリの不具合ではなく、測り方の問題です。**
`.btn` だけが `transition:background .12s` を持っているので、`data-theme` を切り替えた直後に
`getComputedStyle` すると **まだ変わりきっていない色**（切り替え前の `--accent`）が返ります。
同じ色を使う `.chip.src-user` は transition が無いので 7.98 で通ります。
単独で測り直すと、暗いときの主ボタンは `#08201F` × `#4FC3BC` ＝ **7.98** で、基準の 4.5 を超えています。
Windows の Edge で落ちていないのは、おそらく端末側で「動きを減らす」が効いているためです。

### `walkthrough.js` の「ファイルから資料を渡す」は、まれに落ちる

同じ条件で **11回まわして3回** 落ちました（落ちるのは毎回この1か所だけ）。
2026-09-13 に Linux ＋ Chromium で7回まわしたときも **3回**。毎回この1か所だけで、
文面も同じ（`ファイルの中身が入らない`）。**連続では落ちません。**
`FileReader` の完了が、ヘッドレスの仮想時間の下で `waitFor` に間に合わないことがあります。
**落ちたら、もう一度走らせて続けて落ちるかを見てください。**
続けて落ちるなら本物、1回で直るなら環境の揺れです。

### 結果を `FAIL ::` の全文検索で拾わないこと

ヘッドレスの `--dump-dom` には **テスト自身のソースも入っている**ので、
`walkthrough.js` の中の `` `FAIL :: ${name}` `` という文字列に当たり、
**全部通っていても「失敗あり」に見えます**（実際に一度そう読み違えました）。
CLAUDE.md の「画面を丸ごと検索して危険と判断しない」と同じ穴です。
上の例のように **`合計 … 件 / 失敗 … 件` の行だけを拾う**か、
`<pre id="TESTRESULT">`（`SCENARIO` / `PROBE` / `WALK`）の中だけを見てください。
