# 「わたしのこと」タブの見直し（2026-09-26）

本人の問い：**「わたしのことタブは何のためにあるのか、機能しているのか、もっと仕組みやUI、UXを改善できないか。
論文やライフOS、世に出ている似たシステムなど、調べつくした上で参考にして判断して」**。

## 1. 何のためにあるのか

CLAUDE.md の決まりを並べると、このタブの役目は2つある。

1. **アプリが覚えている「あなた」を、見て直せる場所**（決まり2・3b）。
   AIの推測と本人が決めたことを分けて見せ、違っていたら直す。
2. **予定表に入らないものの置き場**（決まり6f）。続けたいこと・気になっていること・あとで見返すこと・こうしてほしいこと。

## 2. 機能していたか（コードと実測）

| 中身 | 何に効いていたか | 判定 |
|---|---|---|
| こうしてほしい（preference） | `planFor` が読む。予定の組み方が変わる | **働いている**。ただし**タブのいちばん下**にあった |
| 会話から集まったこと（profile） | AIに渡す文に入るだけ。予定の組み方には効かない。AIが無いときは何にも効かない | **半分**。使われていることが画面から見えない |
| 続けたいこと（goal） | 一覧に並ぶだけ。予定にも、続いているかの記録にもつながらない | **働いていない** |
| 気になっていること（idea） | 並ぶだけ。やることにするには「…」→「訂正」→種類を変える、の3手 | **ほぼ働いていない** |
| あとで見返すこと（memo） | 食事の質問に答えるときだけ使う | 限定的 |
| まだ聞いていないこと | 押すとチャットで質問が出る | 働いている |

読み取りの側にも穴があった（実測）：
- 「朝のほうが集中できるタイプ。」→ **体調**として記録（その日かぎり・翌日は効かない）
- 「集中できるタイプになりたい」→ **体調**として記録（続けたいことに出ない）

## 3. 調べたもの

### 論文
- **Kay「scrutable user model（見て直せる利用者モデル）」**（1998〜・Personis）——
  利用者は、システムが自分について何を信じているかを**見て、直せる**べき。透明（システムが見せる）ではなく
  「見て直せる」（人がすること）に重きを置く。→ このアプリの由来の印・訂正の道はこの考えに沿っている。
  [ACM TiiS](https://dl.acm.org/doi/10.1145/2395123.2395129)
- **Li・Dey・Forlizzi「個人情報の段階モデル」**（CHI 2010）——準備→集める→まとめる→**振り返る→行動する**。
  前の段の壁は後ろの段へ連鎖する。→ 集めるだけで**行動につながる出口が無い**のが、このタブの弱点だった。
  [ACM](https://dl.acm.org/doi/pdf/10.1145/1753326.1753409)
- **Gollwitzer & Sheeran「実行意図」メタ分析**（2006・94研究・d=.65）——目標に「いつ・どこで」を
  足すと達成率が上がる。→ **続けたいことを「予定にする」**の根拠。
  [Semantic Scholar](https://www.semanticscholar.org/paper/Implementation-intentions-and-goal-achievement:-A-Gollwitzer-Sheeran/c4deb3507fe725ce6363c1735f1ba83bab20d665)
- **Lally ほか「習慣はどう身につくか」**（2010）——同じきっかけで繰り返すと自動化が進む（平均66日・幅18〜254日）。
  1回抜けても大きく崩れない。→ くり返しの予定にし、**回数を数えるが責めない**（割合や連続日数にしない）。
  [Wiley](https://onlinelibrary.wiley.com/doi/10.1002/ejsp.674)
- **Park ほか「Generative Agents」**（2023）——記憶を新しさ・重要さ・関連で取り出し、ときどき「振り返り」で
  上位の気づきにまとめる。→ 今回は採らない（下の「採らなかったもの」）。
  [解説](https://agentpatterns.ai/agent-design/generative-agents-memory-stream/)
- **「Relational Gains, Privacy Strains」**（CHI 2026・ChatGPT の記憶の利用者研究）——
  記憶で「分かってもらえる」良さと、何を覚えているか分からない不安の両方がある。
  [ACM](https://dl.acm.org/doi/10.1145/3772318.3791635)
- **Nahum-Shani ほか「JITAI」**（2018）——必要なときに、必要な分だけ支援する。→ 将来の通知の考え方。
  [Annals of Behavioral Medicine](https://academic.oup.com/abm/article/52/6/446/4733473)
- **AIの記憶が古くなる問題**——昔は正しかったことが、いまは違う。時間で重みを下げる・書くときに食い違いを
  直す・本人が直せる。[mem0](https://mem0.ai/blog/what-is-memory-staleness-in-ai-causes-risks-solutions)

### 世に出ているもの
- **ChatGPT の記憶**——「保存した記憶」は一覧で見て消せるが、「過去の会話の参照」は**見られない**。
  [OpenAI](https://help.openai.com/en/articles/8590148-memory-faq)
  これに対して Simon Willison は「自分について作られた像を、自分が見られない」ことを強く批判した。
  [simonwillison.net](https://simonwillison.net/2025/May/21/chatgpt-new-memory/)
- **Claude の記憶**——覚えていることを**話題ごと**に並べ、1つずつ見て・直して・消せる。健康などは既定で覚えない。
  [Engadget](https://www.engadget.com/2246397/how-to-edit-claude-memory/)
- **Gemini の個人の文脈**——オン／オフと「保存した情報」の一覧。[Google](https://support.google.com/gemini/answer/16598469?hl=en)
- **Replika の Memory**——覚えた事実をタブで見て、直して、消せる。[Replika](https://help.replika.com/hc/en-us/articles/360000874712-What-does-my-Replika-remember-about-me)
- **Rosebud**（AI日記）——前の日記を覚えていて、**目標と習慣の追跡**・週ごとの振り返りにつなげる。
  利用者が一番ほめるのは「分かってもらえる」と「行動につながる」。[Rosebud](https://help.rosebud.app/ai-analysis/long-term-memory)
- **LifeOS / TELOS**（Daniel Miessler）——目的・目標・課題を書き出し、AIがいまの状態と理想の差を埋める。
  →「まだ聞いていないこと」の質問の型はここから借りている（答えは本人の保存先にだけ置く・決まり11）。
  [TELOS](https://danielmiessler.com/telos)
- **GTD の「いつか／たぶん」と週の見直し**（David Allen）——リストは見直してこそ意味がある。
  見直さないと「罪悪感の墓場」になる。[Todoist](https://www.todoist.com/productivity-methods/weekly-review)

## 4. 判断と、入れたもの

調べたものが揃って言っていたのは、**覚えるだけでは足りない。見て直せて、行動につながること**。
このタブは「見て直せる」まではできていたが、**行動への出口**が無かった。だから出口を作った。

| 入れたもの | 根拠 |
|---|---|
| **続けたいことに「予定にする」**。時刻・長さ・くり返しを本人が選ぶと、くり返しの予定が1件できる。時刻は本人が決める（こちらで置かない） | 実行意図（Gollwitzer）・同じきっかけ（Lally）・決まり6a |
| **予定にした目標に「この7日で◯回（予定は◯日）」**。本人が押した完了を数えるだけ。割合・連続日数・点数にしない | 段階モデルの「振り返り」・Lally（1回抜けても崩れない）・決まり3 |
| **気になっていることに「やることにする」**（1回）。いつ言ったかを行に出す（古いほど見直しどき） | GTD の見直し |
| **並びを「いま効いているもの」から**：続けたいこと → こうしてほしい → 会話から集まったこと → 気になっていること → あとで見返すこと → まだ聞いていないこと → 資料 | 段階モデル（行動に近いものを前へ） |
| **「〜なタイプ」「〜な体質」で言い切る文は、わたしのこと**。「〜になりたい」は続けたいこと | 見て直せるモデルは、正しく入って初めて役に立つ |
| タブの説明を「予定表の外で、覚えておくこと。」に（前の「日をまたいでも変わらないこと」は、気になっていることやメモに当てはまらなかった） | ― |

**欄もタブも増やしていない**（タブは4つ）。どれも、今ある行にボタンを1つ足したか、並べ替えたか。

## 5. 採らなかったもの（理由つき）

| 案 | 採らなかった理由 |
|---|---|
| AIが週ごとに「あなたについての気づき」を書く（Generative Agents の振り返り・Rosebud の週の振り返り） | **推測を事実のように見せる**（決まり2）。「集中力が落ちています」のような文は、体調を数値化しない決まり（3）にも触れる |
| 連続日数・達成率の表示（習慣アプリによくある） | 1回抜けただけで0に戻る表示は、Lally の知見（1回抜けても崩れない）と合わず、**責める道具**になる |
| わたしのことを予定の組み方に自動で効かせる（「朝型」なら午前に置く） | 本人が言っていない場所に置くことになる（決まり6a） |
| 古いわたしのことを、自動で消す・薄める | 勝手に捨てない（決まり「勝手に古い記録を捨てない」） |

## 6. 本人に決めてもらいたいこと（次の候補）

1. **古くなったわたしのことを、ときどき聞き直すか**——半年前の「朝型」がいまも本当か。
   消さずに「まだ合っていますか」と1件ずつ出す形なら、決まりに触れない。
2. **気になっていることを、週に1回だけ知らせるか**（APKの通知）——見直さないリストは墓場になる（GTD）。
   ただし通知は増やしすぎると嫌われる（JITAI「必要なときに、必要な分だけ」）。
3. **体のことをAIに送るか**——Claude の記憶は健康などを既定で覚えない。このアプリは「体のこと」も
   AIに渡す一覧に入っている（APKでは記録は端末の外に出ないが、AIへの依頼文には入る）。

## 7. 本人が決めたこと（2026-09-26）

本人の言葉：**「体のこともAIに入れる。気になっていることを通知で知らせるようにする。
古くなったかもしれないことも時々聞き返す。AIの今週のあなたについての気づきは採用したい。」**

6章の3つは全部「やる」、5章で採らなかった「AIの気づき」は**採る**と決まった。入れ方：

| 決めたこと | どう入れたか | 守ったこと |
|---|---|---|
| 体のこともAIに入れる | この7日の体調の申告（本人の言葉・日時つき）と「体のこと」のわたしのことを、本体と速い返事の両方の依頼文に**別の欄で**渡す（前は体調の申告を1つも渡していなかった） | 診断しない・病名を出さない・数値にしない、と依頼文に書く（決まり3） |
| 気になっていることを通知で | **週に1回の見直し**（設定で曜日・時刻を選ぶ。既定は日曜20時・「知らせない」も選べる）。APKでは閉じていても通知が鳴り、押すと「わたしのこと」が開く。Artifact では会話の下のカードに「今日は見直しの日」 | 3つを**1つの通知にまとめる**（通知を増やしすぎない・JITAI） |
| 古いことを時々聞き返す | 最後に言った・確かめた日から90日たったわたしのことを、「まだ合っていますか？」としていちばん上で聞く。1回に2件まで。「まだ合っている」なら次の90日は聞かない | **消さない・薄めない**（勝手に捨てない）。答えるのは本人 |
| AIの今週の気づき | 「今週の気づきを作る」を押すと、AIがこの1週間の発言を読んで1〜3個。**「合ってる」を押したものだけ**わたしのことに入る | 5章の心配（推測を事実に見せる）への手当て：①「AIの気づき（推測）」の印 ②**本人の発言をそのまま引いた根拠**が無いものは捨てる ③「〜ようです／かもしれません」で終わらないもの（断定）は捨てる ④点数・割合・病名に近い言葉は捨てる ⑤押すまでAIに渡さない ⑥作るのは週に1回まで |

**画面で1件すり抜けた。**「うつ傾向があります」が、病名の判定（「うつ病」だけを見ていた）をくぐって
そのまま出た。病名の一部まで広げ、さらに**推測の形で終わるものだけ**通すようにした。
テストでも「8割の日に疲れているようです」がすり抜けたので、割合も止めた。
