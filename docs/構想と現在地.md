### いちばん大事な発見

**#1・#6・#7 が止まっている理由は同じひとつです。**

> このアプリは **ブラウザのタブを開いている間しか存在しない**。

- 観測するには、見ていない間も動いている何かが要る。
- 向こうから声をかけるにも、見ていない間も動いている何かが要る。
- ローカル推論にも、モデルを置いておける場所が要る。

端末の性能でも、モデルの選び方でもありません。**常時動いているものが1つも無い**ことです。
本人が資料で言っている「AIモデルより観測システムが重要」は、ここでも当たっています。

## 2. 2つの指示がぶつかっている（先に決めてもらう必要がある）

| 2026-09-11 に言われたこと | 2026-09-12 に言われたこと |
|---|---|
| 「感情・集中度・健康状態の**根拠のない数値や診断を生成しない**」 | Current State に「**集中度、疲労**、睡眠、仕事量」を統合したい |

いまのアプリは前者に従って作ってあります（`condition` は本人の言葉と日時だけ。点数を持たない）。

**提案する折り合い**：**測れるものは数値で持ち、合成スコアは作らない。**

| 持ってよい（観測できる事実） | 作らない（根拠のない合成値） |
|---|---|
| 実際に何分そのアプリを触っていたか | 「集中度 72」 |
| キーもマウスも触っていない時間（放置秒） | 「疲労レベル 3」 |
| 本人の申告「眠い」「だるい」＋その時刻 | 「Energy 62/100」 |
| 就寝・起床として本人が言った時刻 | 「今日のコンディション：普通」 |

「今日は集中できていない」とAIが言うなら、根拠は
**「14時から3回アプリを切り替えて、そのたび5分以内に戻っている」**のような
**観測した事実**であるべきで、点数ではない、という考え方です。
この折り合いでよければ、`CLAUDE.md` の規則3を書き足します。

## 3. 改善策（順番が大事。上から順に、依存関係の通りに並べてあります）

### 段階1 — 置き場所を変えずに、今日からできること

**1-a. PCの観測を始める** … `tools/observe.ps1`（**この日、動くものを作って実行済み**）

いま手前にあるウィンドウのアプリ名・題名・時刻・放置秒だけを、決まった間隔で1行ずつ書き留めます。
何もインストールしません（Windows標準の `user32.dll` を呼ぶだけ）。通信もしません。

```
時刻      アプリ    ウィンドウの題名   放置秒
17:20:57  claude    Claude             28
```

取らないもの：キー入力の中身、画面の絵、通信の中身。
書き出し先は `%LOCALAPPDATA%\personal-ai-observe\`（**リポジトリの外**）。

**1-b. 観測ログをアプリに渡す**
アプリには既に「自分で渡す欄（貼り付け・ファイル）」があります。まずは**手渡し**で十分です
（自動で送るには常時稼働が要る＝段階3）。

**1-c. 行動 → 意図推定**
ここが安く作れます。**新しいAIは要りません。**
アプリには既に `matchOpenTask()`（言葉と未完了タスクを突き合わせる仕組み）があり、
テストで動いています。ウィンドウの題名を同じ仕組みに通すだけです。

> 「`研究計画書 - Google ドキュメント`」を 35分 → 「**『研究計画書を書く』を35分進めた？**」と聞く

これで #1 と #4の前半が、部分的にですが**本当に立ちます**。
重要なのは **「Chromeを35分」で終わらせない** という本人の要求に、これが直接答えていることです。

**1-d. 「なぜそう判断したか」を残す**（#2の穴）
いまの `history` は訂正しか残していません。「後回しにした」「今日はやらないと決めた」の
**理由**を同じ場所に残せば、「前回はこう判断した」が言えるようになります。

### 段階2 — 段階1の観測データが溜まってから

**2-a. 仮置きの所要時間を、実測で置き換える**
いまタスクの所要時間は「言われなければ30分」の仮置きです（画面にもそう出しています）。
観測ログがあれば、**実際にかかった時間**が分かります。
これは #3「今の自分」の中で、**唯一の根拠のある数値**になります。

**2-b. 生活の側（#5）に手を伸ばす**
食事・睡眠・運動は、いまは本人の申告だけです。観測が始まっても、
**PCから分かるのは仕事の側だけ**です。ここは正直に言うと、
スマホ側のデータ（Health Connect の書き出しなど）を手で渡す形が現実的です。

### 段階3 — 「置き場所を変える」決断が要ること

**#1の自動取り込み・#6のAI側から声をかける・#7のローカル推論は、3つとも段階3です。**
どれも「見ていない間も動いている何か」が前提だからです。

選択肢は2つ。どちらも**今の最大の利点を失います**。

| | このPCで常時動かす | どこかに置いて常時動かす |
|---|---|---|
| 観測の自動取り込み | できる | PCから送る仕組みが別途要る |
| 向こうから声をかける | PCが起きている間だけ | **できる** |
| ローカル推論 | できる（速度は未測定） | 置き場所次第 |
| スマホから開くだけ | Wi-Fi内のみ。外出先で使えない | できる |
| `db`（claude.ai の保存） | **失う**。自前で作り直し | **失う** |
| 費用 | 0円 | **かかる** |
| 個人データの外部送信 | 増えない | **増える**（#7の方針と正面からぶつかる） |

**いま決める必要はありません。** 段階1・2は今の置き場所のままできます。
段階1をやってみて、**観測ログが本当に役に立つか**を見てから決めるのが順当です。
役に立たなければ、常時稼働の議論そのものが要らなくなります。

## 4. Androidの観測について（正直な限界）

本人が主に使うのはAndroidですが、**PCと同じことはできません**。
アプリを1つ入れずに前面アプリを継続的に取る方法がありません。
使用状況（Digital Wellbeing）も歩数（Health Connect）も、
**手で書き出して渡す**のが現時点で唯一の道です。
「移動」「運動」まで自動で取りたいなら、**Androidアプリを作る**話になります（段階3より先）。
