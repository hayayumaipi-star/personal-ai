## 1. 構想の整理

### 最終目標
発言・行動・予定・思考・体調を継続的に理解し、次の行動を提案し、実際の進み具合に合わせて
タスクと予定を調整する専属AI。将来は栄養・コンディショニング支援まで含む。

### 最初に検証する価値（v0.1 で確かめたこと）
> **話したことを放り込むと、根拠をたどれる形でタスクと予定になり、
> 今日の案が出て、訂正するとその場で計画が作り直される。**

ここが成立しないなら、行動の常時取得も健康データ連携も意味を持ちません。逆にここが成立すれば、
あとは入力源（音声・PC操作・健康データ）を増やすだけで構想に近づきます。

### まだ決まっていないこと
- 常時稼働をどこで行うか（このPC／別のサーバー／クラウド）。現状 v0.1 は「開いたときだけ動く」。
- 音声認識をどこで行うか（Androidのキーボード音声入力で十分か、専用の録音アプリが要るか）。
- 健康データの取り込み方（Health Connect の手動書き出しか、アプリ連携か）。
- 友達との共同開発の形（このHTML1枚を共有するのか、GitHubに置くのか）。
- 「行動の自動取得」をやるかどうか。PCの操作監視はプライバシー負荷が大きく、価値の検証が先。

**ローカルAI（ローカル推論）について**: 当時ここに「GPUが内蔵の低性能品なので実用にならない」と
書きましたが、**確かめずに書いた推測で、GPUの部分は誤りでした**。
2026-09-12 に実測したところ、この端末でも **WebGPU は使えます**（`shader-f16` あり）。
不採用の理由は別のところ——**アプリを claude.ai の Artifact に置いている限り、
モデルの重みを取りに行けない**（CSP）——にあります。
詳しくは `docs/ローカルAI調査.md`（調査日・出典つき）。
ただし **ローカル保存とローカル推論は別の話** です。保存だけなら何の問題もありません。

### 比較した3案

**A. 既存の「わたしの秘書」を拡張する** — 不採用
- 実物: Next.js + Cloudflare D1 + ChatGPTログイン。日本語UIで、メモを手入力してタグを付け、CSVに書き出す。
- 良い点: 日本語で作られている。ログインと保存の仕組みが既にある。
- 不採用の理由:
  1. データ構造が `entries` 1テーブルだけで、`content/kind/due/status` しかない。
     **原文・抽出・推測・訂正を区別する場所が無い**。今回の設計の核心が入らないので、
     結局スキーマから作り直しになる。
  2. 抽出も計画も訂正も未実装。実質「タグ付きメモ帳」で、再利用できるのはCSS程度。
  3. 動かすのに Node.js 22 以上が必要だが、このPCには入っていない。
  4. ChatGPT Sites という配布基盤に縛られる。

**B. LifeOS（Daniel Miessler）を土台にする** — 不採用
- 公式GitHubで確認した事実:
  - 「a capable AI coding harness — we build and run on Claude Code — and bun」が前提。
  - ターミナル導入は `curl ... | bash` で、案内されているのは macOS / Linux。
  - **Windowsはネイティブ非対応**（bash と macOS 固有の通知・音声機構に依存）。
  - ライセンスは MIT。データは `~/.claude` 配下に置かれる。
  - **ローカルモデル対応は「実装済み」ではなくロードマップ**。同じくリモートアクセス、
    外部通知（Email/Discord/Telegram/Slack）もロードマップ。
- 不採用の理由: **このPC（Windows）では動かない**。加えて Claude Code を開いている間しか
  動かないため「スマホから開く」に直結しない。**ただし思想は参考になるので、後で読む価値はあります。**

**C. 小さな独立アプリを新規に作る** — ★採用
- 理由:
  1. 原文・確定・推測・訂正を分ける**データ構造をこちらで決められる**。これが今回の本体。
  2. 依存ライブラリゼロの HTML 1ファイルなので、Node も Python も Git も不要。このPCで動く。
  3. claude.ai のページとして公開すれば、**Androidのブラウザからそのまま開ける**。
     アプリのインストールもLAN設定も不要。
  4. 中身が1ファイルなので、友達に渡すのも読んでもらうのも簡単。

### 選んだ構成と、その評価

| 項目 | 内容 |
|---|---|
| 形 | HTML 1ファイル（依存ライブラリなし）を claude.ai の Artifact として公開 |
| 対応端末 | Android・iPhone・PC のブラウザ。あなたのClaudeアカウントでログインした人だけが開ける |
| スマホでの使いやすさ | 縦1カラム＋下タブの構成。ボタンは高さ40px以上。文字入力はスマホのキーボード音声入力が使える |
| データ保存先 | claude.ai 側のあなた専用データベース ＋ 端末のlocalStorage（控え）。**あなたが選択** |
| AIへの送信 | 既定では送信しない。「AIにも読ませる」を押したときだけ、そのメモ本文をClaudeに送る |
| 費用 | 0円。あなたのClaudeアカウントの枠を使うため、別途API契約は不要 |
| ライセンス | 自作コードのみ。第三者ライブラリを使っていないのでライセンス上の制約なし |
| 保守負担 | 1ファイル・約1,200行。外部依存が無いので、ライブラリの更新に追われない |

**あえて選ばなかったこと**: ローカルサーバー（Python/Flask）。Pythonの新規インストールが必要で、
スマホから使うにはPCの電源とWi-Fiと ファイアウォール設定が要り、外出先では使えません。
データを1バイトも外に出したくない場合は、こちらに切り替える価値があります（`docs/残タスク.md` 参照）。

## 3. 実装上の判断

| 判断 | 理由 |
|---|---|
| **ルール抽出を主、AIを従にした** | 無料・即時・オフライン可で、AI障害時も機能が落ちない。AIは「押したときだけ」の上乗せ |
| **1行＝1話題として抽出する** | 話し言葉では「今日中にやる。15分くらい。」のように所要時間が次の文に分かれる。文単位だと取りこぼす（実測で発覚） |
| **読み取り結果は全部「未確認」** | 「曖昧な発言から期限や予定を勝手に確定しない」の実装。確定はあなたのタップのみ |
| **曜日なしの「来週」は日付にしない** | 「来週の金曜」は確定できるが「来週」は確定できない。`duePrecision:"week"` として区別し、画面にも「期限があいまい」と出す |
| **現在状態を保存しない** | 保存すると古い状態が現在の事実として残る。毎回 `items` から計算し直す |
| **体調は引用だけ** | 点数（Energy 62/100 のような）は根拠が無い。本人の言葉と日時だけを持つ |
| **重複判定に完了・取り消し済みを含める** | 「完了したタスクが再提案されない」「訂正後に古い情報を使わない」を同じ仕組みで満たす |
| **計画をキャッシュしない** | 訂正・完了・延期がそのまま次の提案に反映される |
| **原文をAI呼び出しより先に保存する** | AIが落ちても入力が失われない |
| **開発用CLAUDE.mdと個人記憶を分離** | `CLAUDE.md` は作り方だけ。生活データは claude.ai 側と端末にあり、このフォルダには入らない |
