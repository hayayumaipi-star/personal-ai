## A. 壊れていたもの

### A1. 未来の日の予定表が 0:00 から始まる 🟡 → **根本から直した（v4.4）**

> **2026-09-13 追記。** 本人の指示で、**時刻を言っていない作業は予定表に置かない**ことにした。
> 下限を置くかどうかの話ではなくなった——**置き場所を言っていないものは、そもそも置かない。**
> 「明日、資料を作る。2時間。」は「この日にやること」に貯まるだけ。
> 「明日の午前中に」「明日14時から」と言えば、その場所に入る。
> これで 0:00 から作業が並ぶことは無くなった。以下は、その判断に至るまでの記録。

**最初にこれを「バグ」として挙げたのは、こちらの間違い。** 本人の指示で決めたことだった。

| 見ている状況 | 実測 | 判定 |
|---|---|---|
| 今日の0:00に開く | 00:00 から作業を置く | **仕様**（CLAUDE.md 6f） |
| 今日の3:10に開く | 03:10 から作業を置く | **仕様**。起きて開いている、という根拠がある |
| 明日の予定表 | 先頭が 00:00–01:00 | 根拠は無いが、**その日になれば直る** |

未来の日に下限（07:00 など）を置くと、それは「あなたは7時前には作業しない」という
**こちら側の推測**になる。このアプリは一貫してそれを避けてきた（体調を数値化しない、
曜日を言っていない「来週」を期限にしない）。同じ理屈で、起きる時刻も決めない。

### A2. 日をまたぐ予定が、翌日の予定表に出ない 🔴 → **直した**

```
「夜11時から深夜1時までゼミ」
  直す前 → 23:00–00:00（当日だけ）。翌日の0:00–1:00は空き扱いで、そこに作業が置かれた
  直した後 → 当日 23:00–24:00 ／ 翌日 0:00–1:00「前の日から続いています」
```

`planFor` が **その日に「かかっている」予定**を集めるようにした（開始日で選ばない）。
あわせて2つ直した：

- **範囲の終わりが始まりより前のとき**、一律に ＋12時間していた（23:00〜13:00 の14時間になる）。
  まず ＋12 で解けるかを見て、解けなければ翌日にする。
- **範囲の言葉は両側に付く**（「夜11時から**深夜**1時まで」）。
  正規表現の片側にしか午前・午後が無かったので範囲として拾えず、終わりが1時間の仮置きになっていた。

### A3. AIに渡す用事が「古い順で40件」🔴 → **直した**

`contextForAI` の `.slice(0, 40)` が作成順の先頭40件を取っていた。
**db の `orderBy` を付け忘れていたのと同じ型の間違い**で、症状も同じ（黙って劣化する）。

```
開いている用事 60件
  直す前 → 用事01〜40。直前に足した「用事60」は渡らない
  直した後 → 用事60 が渡り、用事01 が落ちる
```

並べ方は ①今日の用事（期限切れ・今日・明日・`targetDay` が今日）を先に ②あとは新しい順。
切り落とした件数は依頼文に「ほかに◯件の古い用事があります」と書いて、件数を答えさせない。

### A4. 資料の後半24,000文字が、黙って読まれない 🔴 → **直した**

| 定数 | 直す前 | 直したあと |
|---|---|---|
| `DOC_MAX_CHARS` | 60,000文字 | 60,000文字 |
| `AI_CHUNK` × `AI_MAX_CHUNKS` | 6,000 × **6** = 36,000 | 6,000 × **10** = **60,000** |

`AI_MAX_CHUNKS` を定数で持たず `Math.ceil(DOC_MAX_CHARS / AI_CHUNK)` から出す。**二度と離れない。**
確認の画面に所要時間と、読み切れない分があるときは「後ろの◯文字は読みません」を先に出す。

### A5. 書き出せるのに、取り込めない 🔴 → **直した**

「読み込む（JSON）」を足した。**いまの記録は消さない。足すだけ。**
同じものは id と `dedupeKey` と `hash` で二重に入れない。
会話は日ごとに突き合わせて混ぜる。設定も控えのものに戻す（確認画面に明記）。

### A6. 「全部消す」が全部消えていない 🟠 → **直した**

| 対象 | 直す前 | 直したあと |
|---|---|---|
| **読み込めていない1000件超** | 残る | **消し切る**（`wipeCollection` が空になるまで回す）|
| 入力中の下書き（DRAFT） | 残る | 消す |
| 消した件数 | 出ない | **数えた数をそのまま出す** |
| 設定 | 残る | 残す（記録ではないので、意図して残している）|

### A7. 2か所で開くと、会話が片方消える 🟠 → **直した**

会話は日ごとに1ドキュメント。**読まずに書くと、もう一方の端末の発言が丸ごと消えていた。**
`pushTurn` が書く前に保存先の同じ日を読み、発言 id で突き合わせて混ぜるようにした。
読めなかったときは今までどおり手元のぶんを書く（消えるより残るほうを採る）。

### A8. タイムゾーンを変えると、保存済みの予定が消える 🟡 → **直した**

`dayKey` は保存値、実時刻は ISO。タイムゾーンを変えると両者がずれて、
その日の予定表からその予定が出なくなっていた。
変えたときに `retimeItems()` が全部の日付を引き直し、履歴に残して、何件直したかを出す。
あわせて選べるタイムゾーンを2つから11に増やした。

### A9. AIが返ってこないと、送信ボタンが押せないまま 🟠 → **直した**

`AbortController` で時間切れを入れた（速い返事25秒・読み取り90秒）。
切れたら「AIの返事が来なかったので、ルールだけで読み取りました」と出してルールに戻る。

### A10. 長い貼り付けで画面が固まる 🟡 → **直した**

原文だけ文字数の上限が無く、10万文字で19.5秒フリーズ、256KiBを超えると保存も落ちていた。
1回の発言の上限を **20,000文字**にして、超えたら先に確認を出す。
そのとき「長い文章は『わたしのこと』の資料として入れると全文が残ります」と案内する。

## B. 仕組みとして足りなかったもの

### B1. くり返しの予定が作れない 🔴 → **直した**

```
「毎週月曜10時からゼミ」
  直す前 → event「毎週 ゼミ」9/14 10:00 の1回きり。次の月曜には出ない
  直した後 → 毎週の月曜に出る。見出しは「ゼミ」、印は「毎週月」
```

対応：毎日 / 平日 / 毎週 / 毎週◯曜 / 毎月◯日 / 隔週。
**項目は1件のまま。** 毎週のゼミを52件の記録にしない（`planFor` がその日のぶんを組み立てる）。
完了は **その日のぶんだけ**（`doneDays`）。シリーズごと消えない。
「この日はやらない」（`skipDays`）も足した。

### B2. 何日も続く予定が作れない 🟠 → **直した**

「明日から3日間、出張します」「14日から16日まで旅行」を、期間として読む。
**3日とも予定表に出る。** 時刻を言われていなければ終日あつかい。
**終日の枠は作業時間をふさがない**（旅行中でも読書はできる）。
ふさぎたいときは「その日は予定を入れないで」と言えば止まる。

### B3. 予定の重なりを黙って重ねる 🟠 → **直した**

```
14:00–15:00 打ち合わせ ／ 14:30–16:00 面談
  → 「予定が重なっています。14:30–15:00：「打ち合わせ」と「面談」」
```

タイムラインより**下**に出す（6f）。どちらを動かすかは決めない。

### B4. 記録を整理する手段が「全部消す」しかない 🟠 → **直した**

- **1件だけ完全に消す**（訂正シートの「記録ごと完全に消す」）。「取り消す」との違いを書いてから消す。
- **古い記録だけ整理する**（3か月／6か月／1年より前）。消すのは
  **終わった・取り消した項目と、それだけから出来ている原文・会話**だけ。
  やりかけのものは、どれだけ古くても残す。
- **記録をさがす**（設定タブ）。原文と項目をまとめて探せる。タブは増やしていない。

### B5. 過ぎた予定が open のまま増え続ける 🟡 → **直した**

予定にも「終わった」ボタンを出した（今まで `task` にしか出ていなかった）。
済んだ打ち合わせを「取り消す」しかなく、その日の振り返りに出席した予定が1件も出なかった。

### B6. 用事が増えると、予定表が意味を失う 🟠 → **直した**

```
期限の無い用事30件
  直す前 → 今日にも1週間後にも同じ30件が並ぶ（どの日も同じ顔）
  直した後 → 未来の日には「その日までに片づけるもの」だけ。今日は今までどおり全部
```

### B7. 日付をまとめて飛べない 🟡 → **直した**

日付バーに「日付」ボタン（端末のカレンダー）。◀▶ を30回押さなくてよくなった。

### B8. 外との接点

| | 状態 |
|---|---|
| カレンダー連携（.ics） | **足した。** 読み込みと書き出しの両方。**認証も外部送信も無し**（ファイルを読む・書くだけ）|
| 知らせ | **開いている間だけ**「あと◯分で『◯◯』です」と出す。端末の通知は使えない（ページを閉じていると何も動かない）|

## C. 画面まわり → **全部直した**

| 項目 | 直したこと |
|---|---|
| Escape でシートを閉じる | 足した |
| シートの背後のスクロール | `body.sheetopen{overflow:hidden}` で止めた |
| シートを開いたときのフォーカス | 中の最初の操作へ移し、閉じたら**元のボタンへ戻す** |
| Androidの戻るボタン | シートが開いていれば閉じるだけにした（**実機での確認はまだ**）|
| 送信中にページを閉じる | 確認を出す |
| 話しかけると今日に戻る | **変更が落ちた日**を見せるようにした（別の日を見ていても飛ばされない）|

> **`history.back()` を自分から呼んではいけない。** 2つの理由で実際に壊れた：
> ① 自分で呼んだ back は遅れて popstate として返るので、その間に開いた次のシートを閉じる。
> ② **headless Edge ではページが終わらなくなり、4つのテストが全部止まる。**
> `pushState` は安全。戻るボタンは「積んでおいて、押されたら受け取る」だけにする。
