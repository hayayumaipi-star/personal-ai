# ローカルAIの可能性（調査日 2026-09-12）

「ローカルAI」は2つの別の話です。混ぜると判断を誤ります。

- **ローカル保存** … データを外に出さない。**これは今も実現しています**（`db` は本人のアカウント内、
  `localStorage` は端末内。AIに渡すのは `profile` の短い文だけ）。
- **ローカル推論** … 言葉を読む処理そのものを手元で動かす。**こちらが今回の調査対象**。

2026-09-11 の `設計判断.md` には「このPCではローカルAIは実用にならない」と書きましたが、
根拠の一部（GPUが使えない）は**確かめずに書いた推測でした**。今回実測して訂正します。

## 0. この端末で実測したこと（2026-09-12）

| 項目 | 実測値 | 前回の記述 |
|---|---|---|
| CPU | Intel Pentium Silver N5030 / 4コア4スレッド / 1.10GHz | 同じ |
| メモリ | 7.8 GB（実行中の空きは 1.9 GB） | 同じ |
| GPU | Intel UHD Graphics 605 / VRAM 1,024 MB | 同じ |
| 空きディスク | 58.9 GB / 114.0 GB | 未記載 |
| **WebGPU** | **使える**（adapter: intel / gen-9、device 取得成功、`shader-f16` あり） | **「内蔵GPUなので無理」と書いていた。誤り** |

`navigator.gpu.requestAdapter()` と `requestDevice()` がこの端末で実際に成功しました。
つまり **ブラウザからGPUを使う道は開いています**。速度が足りるかは別の話で、まだ測っていません。

## 1. 調べた3つ（これ以上は広げない）

### A. WebLLM（MLC）— ブラウザの中でモデルを動かす

| | |
|---|---|
| 実装済み | WebGPU で動く推論エンジン。公式README が "leverages WebGPU" と明記 |
| モデルの入手先 | **実行時に `https://huggingface.co/mlc-ai/…` から取得**（`src/config.ts` の `prebuiltAppConfig`） |
| 一番小さいモデル | SmolLM2-360M-Instruct-q4f16_1 … `vram_required_MB: 376.06` / `low_resource_required: true` |
| | gemma3-1b-it-q4f16_1 … `vram_required_MB: 711.07` |
| この端末で動くか | VRAM 1,024MB なので **数字の上では入る**（376MB / 711MB） |
| **不採用の理由** | **このアプリには載せられない**（下の「本当の壁」） |

### B. Chrome 組み込みAI（Gemini Nano / Prompt API）— ブラウザに最初から入っているモデル

| | |
|---|---|
| 状態 | Translator と Language Detector は**安定版**。**Prompt API はオリジントライアル**（正式版ではない） |
| 必要なGPU | 公式要件 **"Strictly more than 4 GB of VRAM"** → この端末は 1GB。**満たさない** |
| GPUが無い場合の代替 | **16GB以上のRAM＋4コア以上** → この端末は 7.8GB。**満たさない** |
| 空きディスク | 22GB以上（これは満たす） |
| **Androidで使えるか** | 公式に **"Chrome for Android, iOS … are not yet supported"**。**使えない** |
| 不採用の理由 | 端末の要件を2つとも満たさない。そのうえ**本人が使うAndroidでは提供されていない** |

### C. 手元でサーバーを立てる（Ollama / llama.cpp）— PCでモデルを動かし、スマホから呼ぶ

| | |
|---|---|
| 状態 | ソフト自体は実在して動く。ただし**このPCへの新規インストールが必要** |
| 速度 | N5030 の CPU 実行。GPUオフロードは Intel 内蔵では実質使えない |
| **不採用の理由** | ①アプリは `https://claude.ai` 上にあるので、`http://localhost` を呼べない（混在コンテンツ＋CSP）。②**PCの電源が入っていないと使えない**。外出先では動かない。③常時稼働の設計が別途必要 |

## 2. 本当の壁は、端末の性能ではなくアプリの置き場所

このアプリは **claude.ai の Artifact** として公開されています。Artifact のページには
プラットフォーム側の CSP（内容セキュリティポリシー）がかかっていて、

- 外部スクリプトは cdnjs / jsdelivr など**決まったCDNからだけ**読める
- **それ以外のホストへの fetch / XHR / WebSocket は全部ブロックされる**（エラーも出ない）

つまり **WebLLM の本体（JS）は jsdelivr から読めても、
モデルの重み（huggingface.co）を取りに行った瞬間に止まります**。
VRAM が足りるかどうか以前に、**モデルを端末に持ってくる手段がありません**。

> これは「今の置き場所ならこうなる」という話です。出典はプラットフォームの仕様で、
> こちらで実測したものではありません（測るには公開中のアプリを汚す必要があるため、やっていません）。

ローカル推論を本気でやるなら、**Artifact をやめて別の場所に置き直す**ことになります。
そのとき失うもの：

- 「スマホのブラウザで開くだけ」で使えること（今の最大の利点）
- `db`（claude.ai 側の本人専用の保存）。自前の保存に作り替えになる
- 0円で済んでいること

## 3. では、いま手元で動いている「AIでない知能」はどれだけ働いているか（実測）

ローカル推論の代わりに、このアプリは**ルールによる読み取り**を主にしています。
`tests/` と同じ経路で、**AIを一度も呼ばずに** 20発言を流して数えました（2026-09-12）。

| | 件数 | 割合 |
|---|---|---|
| ルールだけで処理できた（記録・追加・完了・進捗・質問への回答） | 15 | **75%** |
| AIが要ると判定して本人に伝えた | 2 | 10% |
| 何も起きない（受け止めるだけでよい発言） | 3 | 15% |

**AIが要ると判定された2件**は、どちらも「言い直しの照合」でした
（「資料、思ったより時間かかってる。今日はほかに何を後回しにできる？」のような、
既にある項目と結びつける判断）。

読み替えると、**小さなローカルモデルに期待したい仕事は、すでに 75% がコードで済んでいます**。
残りは「照合」と「温かい一言」で、前者は 360M 級のモデルが得意な仕事ではありません。

## 4. 結論

**いまローカル推論を入れる理由がありません。** 順に：

1. **置き場所の制約で、そもそもモデルを端末に持ってこられない**（第2節）。これが決定的。
2. Chrome組み込みAIは**端末要件を満たさず、Androidでは提供されていない**。
3. 手元サーバーは**PCが起動しているときしか使えない**ので、外出先で話しかける今の使い方に合わない。
4. そして **ルールだけで既に75%** が動いています。残る2件は小さなモデルの得意分野ではない。

**訂正しておくこと**：この端末は **WebGPU が使えます**。前回「内蔵GPUだから無理」と書いたのは誤りでした。
ハードウェアの道は閉じていません。閉じているのは**アプリの置き場所**の方です。

## 5. 条件が変わったら、また考える

- **Artifact をやめて別の場所に置く**と決めたとき（そのとき WebLLM ＋ SmolLM2-360M を実測する価値がある）
- **Chrome for Android に組み込みAIが来たとき**（公式に "not yet supported" と書かれている＝将来計画）
- **GPU付きのPCを用意したとき**（VRAM 4GB超で Chrome 組み込みAIの要件を満たす）

**まだ測っていないこと**：この端末で SmolLM2-360M を実際に動かしたときの速度と、日本語の質。
測るには huggingface.co から約 250〜400MB のダウンロードが要るので、本人に確認してから行います。
